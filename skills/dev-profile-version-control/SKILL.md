# 版管理の作業

作業場所の分離と片付け、取り込み時の衝突の解消、履歴や状態のトラブルからの復旧を、安全の境界と人の承認を守って進める組み合わせ。各工程の中身は単位に任せ、ここでは順序、引き渡す型、振り分けだけを決める。

## 工程

| 識別子 | 工程 | 単位 | 必須 | 受け取る型 | 渡す型 |
|---|---|---|---|---|---|
| `workspace` | 作業場所を作る | `dev-isolated-workspace` | 条件付き（並べて進める、または本線を汚さずに試す） | 原典の参照、作業状態の控え、作業の一覧、作業場所の台帳 | 作業場所の台帳、作業状態の控え、検証の記録 |
| `work` | 作業する | （元の組み合わせの工程） | 条件付き（作業場所を作って作業するとき） | 作業場所の台帳、作業状態の控え | 変更の事実、作業状態の控え |
| `integrate` | 取り込む | （取り込み・確認） | 条件付き（統合するとき・解消や復旧の後に取り込みを完了して確かめるとき。方法と宛先は原典に従う） | 変更の事実、原典の参照、作業場所の台帳、作業状態の控え | 変更の事実、作業状態の控え、検証の記録 |
| `resolve` | 衝突を解く | `dev-conflict-resolution` | 条件付き（未解決のパスがある、または統合後に不整合が見つかった） | 変更の事実、原典の参照、作業状態の控え、設計の判断、業務規則の一覧、ドメインモデル、完了条件の一覧 | 統合の判断表、変更の事実、検証の記録 |
| `contract-ask` | 人が決める | （人） | 条件付き（統合の判断表に未決の契約の変化がある） | 統合の判断表 | 原典の参照 |
| `recover` | 困りごとから戻す | `dev-history-recovery` | 条件付き（押し出し拒否、誤コミット、切り離された状態などのトラブルが起きた） | 作業状態の控え、原典の参照、引継ぎの記録、破壊的操作の計画 | 破壊的操作の計画、作業状態の控え、検証の記録 |
| `destructive-ok` | 破壊的な操作を承認する | （人） | 条件付き（印に「取り返せない」が付く操作、または外部道具の導入がある） | 破壊的操作の計画、作業状態の控え | 破壊的操作の計画 |
| `cleanup` | 片付ける | `dev-isolated-workspace` | 条件付き（片付けまで依頼され、工程 `integrate` で統合と確認を終えた、または統合せず破棄する人の承認がある後） | 原典の参照、作業状態の控え、作業場所の台帳、検証の記録 | 作業場所の台帳、作業状態の控え、検証の記録 |

型の中身は [型の一覧](../dev-shared/references/artifact-types.md) を見る。

外から受け取る型: 原典の参照、作業状態の控え、作業の一覧、作業場所の台帳、変更の事実、設計の判断、業務規則の一覧、ドメインモデル、完了条件の一覧、引継ぎの記録
外へ渡す型: 作業場所の台帳、作業状態の控え、検証の記録、変更の事実、統合の判断表、破壊的操作の計画

### 遷移

入口は、作業場所を作るときは `workspace`、統合するときは `integrate`、衝突を解くときは `resolve`、トラブルから戻すときは `recover`、片付けるときは `cleanup`。

| 元 | 先 | 条件 |
|---|---|---|
| `workspace` | `work` | 作業場所と専用資源の隔離を確かめた |
| `work` | `integrate` | 作業を終えて統合する |
| `work` | `recover` | 作業中に版管理のトラブルが起きた |
| `integrate` | `resolve` | 衝突がある、または統合後に不整合が見つかった |
| `integrate` | `recover` | 取り込みや反映でトラブルが起きた |
| `integrate` | `cleanup` | 衝突なく統合と確認を終えた（または統合せず破棄する人の承認がある）うえで、使っていた作業場所を片付ける |
| `resolve` | `contract-ask` | 未決の契約の変化がある |
| `resolve` | `recover` | 解消中に版管理のトラブルが起きた |
| `resolve` | `integrate` | 契約の判断がそろって解消を終え、取り込みの完了（コミット・続ける操作）と統合確認へ戻す |
| `contract-ask` | `resolve` | 人が契約の選択を決めた（表に従って解き直す） |
| `recover` | `destructive-ok` | 印に「取り返せない」が付く操作、または外部道具の導入が要る |
| `recover` | `work` | 作業中のトラブルを復旧し、作業場所での作業へ戻る |
| `recover` | `integrate` | 復旧を終え、取り込みの完了と統合確認へ進む |
| `recover` | `resolve` | 復旧後に衝突の解消が要る |
| `destructive-ok` | `recover` | 人が破壊的な操作を承認した（やめると決めたときは中止して終わる） |

## 振り分け

一言の依頼から、どの工程に入るかを決める。迷ったら、依頼者に一度だけ聞く。

| 依頼の言い方・状況 | 入る工程 |
|---|---|
| 「worktree で進めたい」「並列で安全に作業したい」「別の作業場所を作って」 | `workspace` |
| 「終わったので本線に取り込んで」「別の枝を統合したい（衝突はまだ無い）」 | `integrate` |
| 「コンフリクトを解消して」「rebase で衝突した」「取り込みで衝突や食い違いが出た」「両方残して統合するか判断して」 | `resolve` |
| 「push が拒否された」「大きいファイルをコミットしてしまった」「秘密をコミットに含めてしまった」「detached HEAD になった」「直前のコミットを取り消したい」 | `recover` |
| 「worktree を片付けて」 | `cleanup` |

## 工程の間の決まり

- どの作業（作業場所の作成・衝突解消・復旧・片付け）でも、変更の前にまず作業状態の控え（未確定の変更と管理外ファイルの復元可能な退避先を含む）を取る。
- 作業場所（工程 `workspace`）では、ファイルだけでなく保存先・実行枠・依存の実体の隔離を実測で確かめてから工程 `work`（作業する）へ進む。共有の常駐処理を分けた作業場所から起動したり作り直したりしない。
- 取り込み（工程 `integrate`）は、原典の参照にある方法と宛先で行い、取り込む前に作業状態の控えを取る。強制送信や履歴の書き換えを伴うなら工程 `recover`（困りごとから戻す）へ回す。統合先で原典の確かめ（ビルド・テスト・静的検査など）を流し、取り込んだ版と結果を検証の記録に残したときに、統合と確認を終えたとする。
- 衝突を解くとき（工程 `resolve`）は、編集の前に統合の判断表を出し、契約が変わる未決の選択があれば工程 `contract-ask` で人の決定を待つ。「全部解消して」「分析して」だけでは承認として扱わない。
- 契約の変化を合成して解消した変更は、解消した担当自身がそのまま承認のレビューを兼ねず、独立したレビューに回す。
- トラブルからの復旧（工程 `recover`）は、秘密情報の誤混入なら報告と失効案内を最優先で先行させ、遠隔がある場合は最新の遠隔取得と Q1・Q2 判定を飛ばさない。印（型の一覧の「段に付ける印」）に「取り返せない」が付く操作や外部道具の導入は計画（強制送信時は確認済み遠隔 SHA を固定）を示して工程 `destructive-ok` で人の承認を得てから実行する。
- 工程 `cleanup`（片付ける）は、工程 `integrate` で取り込みと統合後の確認を終えた後、または統合せず破棄する人の承認・統合済みの明示的な片付け依頼がある後だけに行い、`resolve` や `recover` から直接 `cleanup` へ飛ばない。未確定の変更・未反映の履歴・除外された成果物の退避を済ませ、引継ぎの記録が作業場所を指している場合は片付けの前に記録の「作業の場所」を更新する。

## 終わり方

- 作業場所を使って通しで進めるときや片付けを依頼されたときは、工程 `cleanup` で片付けと専用資源の解放を確かめて終える。
- 作業場所を使っていないとき、または作業場所での作業途中に衝突解消（工程 `resolve`）や復旧（工程 `recover`）だけを依頼されたときは、工程 `integrate`・`resolve`・`recover` で終了条件と検証の記録を満たした時点で作業場所を残したまま元の作業へ返して終える。工程 `destructive-ok` で中止した場合は、破壊的操作を実行せず控えを残した状態で止めて終える。解消の採否はコミットや強制送信の許可を兼ねない。
