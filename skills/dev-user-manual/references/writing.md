# 書き方

[SKILL.md](../SKILL.md) の手順2で、章の本文を書くときの勧め。案件に文体の決まりがあれば、そちらに従う。下の語尾や言い回しは日本語の案件の例。

## 文

- です・ます調。手順は「〜します」で書き、1つの手順に1つの操作を書く。同じ場所で続けて行う短い操作は、まとめてもよい。
- 操作の場所を先に書き、操作を後に書く（「〔設定〕の画面で、〔保存〕を押します」）。
- 画面の操作の動詞をそろえる（例: 「押します」にそろえ、クリックとタップを混ぜない）。
- 条件の分かれが長いときは、手順の中に書かず「うまくいかないとき」の章に移す。
- 「正常に処理されます」だけで終えず、画面で見える結果（一覧に行が増える、表示が変わる）を書く。
- 「それ」「対象」「一覧」だけでは、章を単独で読んだときに何を指すか分からない。画面の正式な名前で補う。

## 章

- 一つの章は、一つの仕事のできた状態まで。
- どの仕事に進むかを決める判断（どちらの手続きを選ぶか、など）は、分かれ目の手前の章に置き、実行の章に同じ説明を重ねない。
- 章どうしは、章の題（仕事の名前）で指す。ファイルの名前や置き場を本文に書かない。
- 所要の目安は書いてよいが、約束の時間は書かない。

## 表紙と目次

- 表紙の副題は、読む人（役割）にする。今回足した機能の要約にしない（後で章を足すと古くなる）。
- 目次は章の題（仕事の名前）で作り、画面の識別子では並べない。
