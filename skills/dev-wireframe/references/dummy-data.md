# ダミーデータの基準

ワイヤーに入れる値の基準。見る人が、値の不自然さではなく、画面の構造と流れに意見を言えるようにするため。

## 作り物にする

- 値は最初から作り物にする。本番の値、実在の個人や組織の値を少し変えたものも使わない。
- メールの宛先と URL は、届かない例示用の名前（`example.com`、`example.org`、`.example`、`.test` など、例示や試験のために取ってある名前）にする。
- 電話番号は、案件の国の例示用の番号があればそれを、無ければ明らかに使われない形にする。
- 名前や数は、現場で見かける形に近づける（「テスト太郎」ばかりにしない、件数や金額の偏りも実際の使われ方に寄せる）。ただし実在の人や組織に寄せず、本番の集計や分布を写さない。

## 食い違わせない

| 組 | 確かめること |
|---|---|
| 合計と内訳 | 内訳を足すと合計になる |
| 件数と一覧 | 表示した件数と、一覧の行の数が合う |
| 日付 | 作った日、直した日、締めの日の前後が、業務の流れと合う |
| 状態と表示 | 状態に合う操作と表示だけが出ている |
| 関係 | 指している相手（取引先、担当者）が、データの中に実在する |

## 1か所にまとめる

- 人、組織、品物の名前は、正本を1か所（データのファイル）に置き、全部の画面がそこから読む。
- 状態の切り替えでデータを変えるときは、依存するデータごと戻せるようにする。
