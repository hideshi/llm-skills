# 静的な HTML

本文の手順（手元で開ける、外部の読み込みに頼らない、画面と状態をそろえる、ダミーデータを1か所に置く）を、使い捨ての静的な HTML で行うときの資料。案件に決まったワイヤーの道具があれば、そちらを使う。

- 確かめた版: Chromium 150.0.7871.181（Linux、`--headless=new`）
- 確かめた日: 2026-11-14
- 【実行】は小さなファイルを実際に開いて確かめたこと。印の無い項は、この資料の勧め（作り方の決まり）で、事実の主張ではない。【経験】は、実案件のワイヤーで起きたことで、この版では確かめていないこと
- 公式の資料: HTML Living Standard（https://html.spec.whatwg.org/ ）

## 置き方

```text
wireframe/
  index.html        画面の一覧（画面の識別子と状態へのリンク）
  common.css        共通の部品の見た目（色は意味の名前で、値は少なく）
  parts.js          共通の部品（枠、移動、ダイアログ、知らせ、注記の欄）
  data.js           ダミーデータ（名前の正本はここだけ）
  SCR-001.html      画面ごとのファイル
  SCR-001--empty.html   状態ごとのファイル（または切り替え）
```

- 画面のファイル名は、画面の設計の識別子と状態にする。ファイルの頭のコメントに、画面の識別子と、もとにした画面の設計の版を書く。
- ダミーデータは画面のファイルに書かず、データのファイルから読む。

## 手元で開く

- **`file://` で開くと、`<script type="module">` は動かない**（【実行】Chromium で、普通の `<script src>` で読んだデータは画面に出て、モジュールで書いた処理は動かなかった。理由は資料では確かめていない）。手元のファイルのまま開くなら、普通のスクリプトで書き、データは `window` に置く。モジュールを使うなら、手元の配信（`127.0.0.1` だけで待ち受けるもの）で開く。
- 外部の読み込み（CDN の部品や文字、分析の送信）を入れない。見せる場で回線が無くても開けるようにし、見た人の操作が外へ送られないようにするため。部品の枠組みが要るなら、ファイルを手元に置く。

## 画面と規則の表し方

- 見出し、移動、本文、表、フォームは、意味の合う HTML の要素で組む（`<nav>`、`<main>`、`<table>`、`<label>` など）。
- 規則の注記は、初めは閉じた注記の欄（`<details>` など）に置く。公開面は注記の欄を出さず、HTML のコメントにする。
- 押せない操作は `disabled` で表し、理由は押せない要素の上に乗った時だけ出すのではなく、周りの要素に文字で置く（見落とされにくく、キーボードや読み上げでも届くようにするため）。
- ブラウザ組み込みの `alert` と `confirm` を使わない。確かめは、共通の部品のダイアログで見せる。
- 状態の切り替えのデモは、データを丸ごと入れ替える形にして、依存するデータが食い違わないようにする。

## 落とし穴

- 【経験】文字の値を組み立てた HTML の属性に直接埋めて、引用符の入った値で表示が崩れた。値は `textContent` や属性の設定の関数で入れる。
- 【経験】横のパネルやダイアログを閉じたとき、裏の一覧の位置とフォーカスの戻り先がずれた。開いたときの位置と、閉じたときのフォーカスの戻り先を、画面の設計の流れと合わせる。
