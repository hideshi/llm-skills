## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 非同期を一律に適用せず理由を明記し、方式の分岐ごとに「選ばなかった案と理由」を1行ずつ書く | 同期で足りる処理まで非同期にして運用と状態管理を複雑化させるのを防ぎ、後から方式選定の背景を追えるようにするため | 非同期化して却って障害切り分けや遅延悪化で同期へ戻した件数と理由の記録を比べ、方式分岐の基準を見直す |
| 中核の6原則への適合を明記し、外部を呼ばない処理では原則6を「対象外」とする | 外部呼び出しの有無で結果不明の扱いが不要な処理まで過剰設計になるのを防ぎつつ、確認漏れを無くすため | 対象外・適合の判定漏れや原則外れで発生した二重実行・取りこぼしの件数を記録し、6原則の適用範囲を見直す |
| 実行中に止まったものの回復先を、外部なし＋冪等なら「待ち」へ、外部ありなら必ず「結果不明」へ分ける | 外部へ送った可能性がある処理を自動で待ちへ戻して二重課金や二重送信を起こすのを防ぐため | 停止回復後に起きた二重送信・二重課金件数と結果不明への滞留件数を実測し、遷移先の分け方を見直す |
| 手動の再送は「1回きりの明示した試行」として記録して自動再試行回数を戻さず、結果不明は再送前に必ず照会を行う | 手動再送で自動再試行ループが無限に再開したり、未確認の外部実行を重ねて二重実行になるのを防ぐため | 手動再送から自動ループや重複実行が起きた事故件数と照会の手間を記録し、再送前の制約を見直す |
| 一部の件の失敗を止めるか続けるかの正本はエラーの設計に置き、無ければ仮に決めて未確認に書く | エラー分類とバッチ継続方針が矛盾するのを防ぐため | 仮決めの後にエラーの設計と食い違って設計をやり直した手戻り件数を記録し、仮決めの条件を見直す |
| 送る内容と試行履歴に残す内容で個人情報を分け、試験では外部送信を捕まえて本物へ送らない | 調査ログや外部サービスの管理画面へ不要な個人情報が滞留することと、検証中の誤送信を防ぐため | 試行履歴への不要項目混入や検証中の誤送信が起きた件数と調査困難になった割合を比べ、履歴の項目絞込を見直す |
| 定期バッチ・一括処理に、起動の排他、区切りごとの途中再開、一部失敗の扱い、時間帯と負荷・上限時間、件数報告をセットで設ける | 大量件数の処理で二重起動や途中停止時の全件やり直しを防ぎ、一部失敗や遅延時の運用方針を設計時点で閉じるため | 5観点（排他・途中再開・一部失敗・時間帯と上限・件数報告）を設けた設計で起きた運用障害と過剰設計による差し戻し件数を問題台帳で比べ、観点の過不足を見直す |
