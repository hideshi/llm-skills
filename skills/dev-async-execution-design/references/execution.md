# 実行の設計

ジョブ、キュー、バッチの実行の詳しい表。「外部を呼ぶとき」と書いた所は、外部サービスや別のシステムを呼ぶ処理にだけ当てる。

## 状態の遷移

| 状態 | 意味 | 次に進める状態 |
|---|---|---|
| 待ち | 意図を保存した。まだ誰も実行の権利を取っていない | 実行中 |
| 実行中 | 実行の権利を取り、処理している | 成功、拒否、再試行待ち、結果不明（外部を呼ぶとき） |
| 再試行待ち | 一時的な障害。決めた時刻の後に、もう一度試す | 実行中、断念 |
| 成功 | 処理ごとに決めた成功の境界を越えた | — |
| 拒否 | 確定した誤り（入力の誤り、相手が確定して断った）。再試行しない | — |
| 結果不明（外部を呼ぶとき） | 送ったかどうか、届いたかどうかが分からない | 成功、拒否、待ち（照会で未実行と確定したときだけ） |
| 断念 | 再試行の上限に達した | 人の判断で待ちへ戻す |

- 実行中のまま止まったもの（担当が落ちたなど）は、決めた時間の後に検出する。閾値は処理ごとに決める（例: 5分）。
  - 外部を呼ばない処理で、冪等である（同じ件を2回流しても結果が同じ）なら、待ちに戻してよい。
  - 外部を呼ぶ処理は「結果不明」にする。待ちに戻さない（二重に実行しないため）。
- 成功とみなす境界（相手が受け付けた、処理まで終わった、など）は、処理ごとに決めて書く。

## 失敗の分け方

- 外部を呼ばない処理: 実行されたかどうかはトランザクションで分かる。再試行してよいか（一時的な障害か、確定した誤りか）だけを分ける。
- 外部を呼ぶ処理: 相手で実行されたかどうか、再試行してよいか、結果が分からないときの照会のしかたは、システム間の連携の設計の判断に書かれた分け方に従う。無ければ、仮に決めて未確認に書き、連携の設計が要ることを人への問いにする。

分け方は1か所にまとめ、どの規則で分けたかを試行の履歴に残す。

## 結果不明の扱い（外部を呼ぶとき）

- 結果不明の状態に入ったものは、自動で再試行しない。照会して確定してから、成功・拒否・待ちのどれかへ進める。
- 照会を誰が、いつ（何分後、何回まで）行うかを決める。

## 人に見せる導線と再送

- 失敗と結果不明の一覧を、担当者が見られるようにする（画面、通知、定期の報告のどれか）。
- 手動の再送は、1回きりの明示した試行として記録する。自動の再試行の回数を戻さない。
- 再送する前に、結果不明のものは照会を先に行う。

## 個人情報

- 送る内容と、試行の履歴に残す内容を分ける。履歴には、調べるのに要る最小限だけを残す。
- 外部の記録（相手の管理画面、ログ）に残るものも、送る内容に含まれると考える。

## 確かめる観点

- 同じ意図が二重に実行されない（実行の権利の取り合い）。
- 業務のデータの保存に失敗したら、意図も残らない。
- 時間切れのとき、結果不明に分けられる（外部を呼ぶとき）。
- 確定した拒否で再試行しない。
- 再送が1回きりで、履歴に残る。
- バッチが途中で落ちたとき、終わった所の続きから再開でき、終わった件を二度処理しない。
- 同じバッチを二つ同時に起動しても、片方だけが動く。

## 参照の形の例

- 定期の集計: 区切りごとに進み具合を保存し、落ちたら続きから再開する。起動の排他はデータベースの行ロックで取る。
- 一括の取り込み: 失敗した行を集めて続け、終わりに失敗の一覧をファイルに出す。その行だけを流し直せる。

- 通知: チャットへの投稿とメールの送信を、意図の表から別々の担当が実行する。
- 問い合わせの受付: 受け付けを保存した後、外部の管理ツールへの登録を非同期で行い、失敗は一覧で見せる。
- 回数の制限がある外部: 間隔を広げながら最大5回まで再試行し、断念したら人に見せる。
