## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 要求は、人が許可を記録で残した、自分たちが管理するホストにだけ送る。許可の記録が無ければ、要求を作るところまでで止める | 第三者のホストへの要求は、許しの無い試しになりうるため。許可の範囲を後から確かめられるようにするため | 許可の範囲の外へ送った件数と、許可の記録が無くて止まった件数を記録し、許可の取り方を見直す |
| 送るのは状態を変えない要求だけにし、値を変えて送る走査や攻撃に当たる要求は送らず、必要なら人に返す | 動いているシステムの状態を変えたり、守りを試したりすると、利用者に影響し、許しの範囲を超えるため | 値を変えないと分からなかった項目が、人に返した後にどう確かめられたかを記録し、返し方を見直す |
| 本番は、許可の記録が本番を含み、普通の利用者と同じ読むだけの要求のときだけ見る | 応答の見出しは本番の前段でしか分からないことがある一方、本番への要求は利用者に影響しうるため | 本番を見なかったために見落とした項目と、本番への要求で起きた影響の件数を記録し、本番の扱いを見直す |
| 項目ごとに適用・判定・対応の三つを分け、方針が無いときに対象外と受け入れを担当が補わない | 「見なかった」と「見て問題が無かった」と「問題を受け入れた」が混ざると、範囲が読めなくなるため | 方針が無いのに対象外とされた項目が、後で問題になった件数を記録し、分け方を見直す |
| 応答だけで判定できる項目と、コードや設定を読む項目を分け、前者を見たことで後者を確かめたことにしない | 走査の道具の合格が、認可や出力の変換の確認の代わりに読まれやすいため | 応答の点検で合格とした後に、コードを読む項目で問題が見つかった件数を記録し、区分を見直す |
| 走査の道具の指摘は、層、実際の版、本文、環境を先に確かめてから判定する | 道具の指摘には、データの窓口だけの見出しの欠け、古い版の文字列、単語の一致などの誤検知が多いため | 誤検知とした指摘が後で本当の問題だった件数を記録し、確かめる順を見直す |
| 点検の記録に、応答の中の秘密、個人の情報、Cookie の値を写さず、攻撃の手順を書かない | 点検の記録そのものが、弱点と内部の構成の一覧になり、漏れると悪用されうるため | 記録の中に秘密や手順が混ざっていた件数を記録し、書かないものの決まりを見直す |
