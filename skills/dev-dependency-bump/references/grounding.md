## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 行き先の版は人が決め、担当は候補を比べて「依存を解決しただけで、入れて動かしてはいない」と明記して渡す | 版の選択は互換と急ぎの得失の判断で、比べの結果を動作の確認と取り違えやすいため | 担当が版を決めて後で戻した件数と、比べの結果を動作確認と読んだ件数を記録し、渡し方を見直す |
| 範囲内の最新化は、旧版がすべての依存元の範囲を満たすなら戻し、戻せるものが無くなるまで繰り返す | 目的と関係の無い間接の依存の変化が、告知の入れ替わりや動きの変化を持ち込むため | 戻した版上げと戻さなかった版上げで、後で問題になった件数を比べ、戻す条件を見直す |
| 直ったことを捕まえる試験は、上げる前の依存で落ち、上げた後の依存で通る両方を、差を依存の組だけにして残す | 上げた後に通るだけでは、試験が直ったことを捕まえているか分からないため | 旧い依存で落ちなかった試験の件数を記録し、試験の作り方を見直す |
| 部品の取得と組み立ては、資格情報やトークンの無い隔離した場所で行い、取得元とロックの差を確かめる | 導入のときのスクリプトが走り、取得元のすり替えや資格情報の持ち出しが起きうるため | 隔離の外で取得した件数と、取得元の差に気づかなかった件数を記録し、隔離の決まりを見直す |
| 直ったことを告知と同じ種類の条件で動きで確かめるかは人が決め、確かめるなら自分で立てた隔離した環境で使う前提で書き、条件の形を記録に書かない | 攻撃に当たる入力を一律に禁じると直ったことを確かめられず、形を広く残すと第三者に使われうるため | 確かめた回と省いた回で、後で直っていなかった件数を比べ、判断の求め方を見直す |
| DB が作り替えられる版上げでは、見込みを書いてから手元で3回指紋を取り、差が出てよい一覧と突き合わせ、説明できない差を残さない | 版上げの作り替えは設定や保存された状態で発動が変わり、本番で初めて差に気づくと戻しが難しいため | 本番の直前と直後の差が一覧に収まらなかった件数を記録し、見込みと実測の取り方を見直す |
| 「直った」は、版の範囲、点検の道具の告知、動きの確認の3種類で根拠を書き分ける | 版の照合は配布元の公表を頼りにしたもので、動きで確かめたこととは強さが違うため | 版の照合だけで直ったとして後で覆った件数を記録し、書き分けの求め方を見直す |
| 載せる成果物と戻す成果物は控えたキーで指し、保管の自動削除はこの回だけ止める | 「最新」や「1つ前」で指すと、間に別の成果物が入ったときに違う世代を載せたり戻したりするため | 違う世代を載せた・戻した件数を記録し、指し方の決まりを見直す |
