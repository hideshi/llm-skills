# CLI での例

本文の決まりを、シェルや運用者、ほかのスクリプトから呼ばれるコマンド（バッチの起動を含む）で書くときの例。案件に既定の決まりがあれば、そちらを優先する。

## 操作の表し方

- コマンド名と下位のコマンドで操作を表す（例: `invoice finalize <id>`）。読むだけの操作と、変える操作を名前で見分けられるようにする。
- 変える操作には、実行せずに何が起きるかだけを示す旗（`--dry-run` など）を用意すると、運用者が確かめてから流せる。
- 二重に流されると事故になるコマンドは、冪等にするか、同時に二つ動かないようにする（起動の排他はバッチの実行の設計で決める）。

## 入力

- 必須の値は位置の引数か必須の旗にし、省けば誤りにする。既定の値に頼る旗は、既定を説明に書く。
- 秘密の値（パスワード、鍵）を引数で受け取らない。引数はプロセスの一覧や履歴に残る。環境変数かファイルで渡す。

## 出力

- 結果（ほかのプログラムが読むもの）は標準出力に、進み具合や警告や誤りは標準エラーに出す。
- ほかのプログラムが読む前提なら、機械が読める形（`--json` など）を用意し、その形を契約として扱う（項目の削除や意味の変更は互換を壊す）。
- 人向けの表示の文言は、契約に含めない（変えてよい）と明記する。

## 終了コード

終了コードは、呼び出したスクリプトが分岐に使う契約。意味を決めて、変えない。

| 回復の動き | 終了コードの例 |
|---|---|
| 成功 | 0 |
| 一部だけ失敗した（失敗の一覧を出した） | 1 または専用の番号 |
| 使い方の誤り（引数が足りない、知らない旗） | 2 |
| 入力の内容の誤り（直して流し直す） | 専用の番号 |
| 時間を置いて流し直してよい（一時的な障害） | 専用の番号 |
| 流し直しても直らない障害 | 専用の番号 |

- 0 以外の番号の意味を、説明と文書に書く。番号の意味を変えるのは、互換を壊す変更。
- 失敗したときは、標準エラーに、何が起きたかと、次にとる行動を書く。相関の識別子があれば添える。

## 互換性

- 旗の削除、名前の変更、既定の値の変更、出力の機械向けの形の変更、終了コードの意味の変更は、互換を壊す。
- 古い旗は、しばらく残して警告を出し、廃止の時期を書く。
