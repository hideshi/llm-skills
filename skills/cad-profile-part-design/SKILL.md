# 部品の設計

部品の 3D モデルを、根拠を確かめてから作り、人が見て採り、試作の実測で直す流れの組み合わせ。各工程の中身は単位に任せ、ここでは順序、引き渡すもの、振り分けだけを決める。CAD の道具には依存しない。道具は受付で選び、組み立ての工程でその道具の資料と雛形を使う。

## 工程

| 識別子 | 工程 | 単位 | 必須 | 受け取るもの | 渡すもの |
|---|---|---|---|---|---|
| `intake` | 受付 | （人と担当） | 必須 | 依頼、案件の指示の文書 | 依頼の記録（部品の役目、入口、使う道具と版、案件の制約） |
| `grounding` | 一次情報を確かめる | `primary-source-grounding` | 条件付き（規格・ルール・市販品の寸法・素材の値に縛られ、記録が無いか、版が古いか、実測と食い違う） | 依頼の記録、一次情報の記録（直すとき） | 一次情報の記録 |
| `policy-ask` | 方針を確かめる | （人） | 条件付き（決めていない方針がある。または未確認の値で仮置きして進めるかを決める） | 一次情報の記録、依頼の記録、方針の案 | 方針 |
| `cad-build` | 組み立てて検査する | `cad-parametric-modeling` | 必須 | 依頼の記録、一次情報の記録、方針、実測の記録 | 設計のスクリプト、生成物、検査の記録、プレビュー、確認の手順 |
| `visual-ok` | 見て採る | （人） | 必須 | プレビュー、生成物、検査の記録、確認の手順 | 採るか、直す所 |
| `fit-feedback` | 試作を測って反映する | （人が試作して測る） | 条件付き（試作する） | 生成物、確認の手順 | 実測の記録、直す所 |

- 依頼の記録、方針、実測の記録は、案件の置き場所（README や一次情報の記録の別の節など）に書く。このスキルのディレクトリには書かない。
- 案件に固有の制約（造形できる大きさ、プリンタ、素材の銘柄）は、案件の指示の文書から受ける。このスキルには書かない。

### 遷移

| 元 | 先 | 条件 |
|---|---|---|
| `intake` | `grounding` | 縛る値に外部の事実があり、記録が無いか古い |
| `intake` | `policy-ask` | 根拠が揃っているか要らず、決めていない方針がある |
| `intake` | `cad-build` | 根拠も方針も変わらない変更（寸法の調整、書き出しの作り直し） |
| `intake` | `fit-feedback` | 試作を測った値を持ち込んだ |
| `grounding` | `policy-ask` | — |
| `policy-ask` | `grounding` | 方針を決めるのに、まだ確かめていない外部の事実が要る |
| `policy-ask` | `cad-build` | 方針が決まった |
| `cad-build` | `grounding` | 作る途中で、根拠の無い縛る値が見つかった |
| `cad-build` | `policy-ask` | 検査を通すのに方針の変更が要る、または検査の閾値を緩める必要がある |
| `cad-build` | `visual-ok` | 検査がすべて通った |
| `visual-ok` | `cad-build` | 形を直す（方針は変えない） |
| `visual-ok` | `policy-ask` | 方針を変える |
| `visual-ok` | `fit-feedback` | 採って、試作する |
| `visual-ok` | （終わり） | 採って、試作しない |
| `fit-feedback` | `cad-build` | 実測でパラメータを直す（すきま、相手の部品の寸法） |
| `fit-feedback` | `grounding` | 実測が一次情報と食い違う、または安全の基準を確かめ直す |
| `fit-feedback` | `policy-ask` | 素材、向き、造形の仕方を変える |
| `fit-feedback` | （終わり） | 人が試作を採った |

## 受付で決めること

- **入口**: 新しく作る、形や仕様を変える、試作の実測を反映する、のどれか。
- **道具**: 次の順で決める。
  1. 依頼者の指定。
  2. 案件の指示の文書の既定。
  3. どちらも無ければ、手元に入っている道具を命令で確かめ（版を出す命令）、候補を挙げて依頼者に聞く。
  - 道具の資料が無い道具を選んだときは、組み立ての工程で、資料の無い道具の確かめ方に従うと依頼の記録に書く。
  - 途中で道具を変えるときは、新しく作るのと同じに扱い、前の道具の生成物と寸法を比べて確かめる。
- **案件の制約**: 単位と座標系、造形できる大きさ、生成物の置き場所を、案件の指示の文書から写す。無ければ依頼者に聞く。

## 振り分け

一言の依頼から、どの工程に入るかを決める。迷ったら、依頼者に一度だけ聞く。

| 依頼の言い方・状況 | 入る工程 |
|---|---|
| 「この部品を設計して 3D プリントしたい」「新しくモデルを作って」 | `intake` → `grounding`（縛る値があれば）→ `policy-ask` → `cad-build` → `visual-ok` |
| 「この寸法を変えて作り直して」「穴を少し広げて」 | `intake` → `cad-build`（根拠や方針に触れるなら `grounding`・`policy-ask` を先に） |
| 「別の規則（版）に合わせて」「素材を変えたい」 | `intake` → `grounding` → `policy-ask` → `cad-build` |
| 「試作を測ったので反映して」「きつくて入らなかった」 | `fit-feedback` → `cad-build` |
| 「STL を書き出し直して」 | `cad-build`（形を変えないことを確かめる） |
| 「この部品の規格の値を調べて」だけ | このプロファイルではなく `primary-source-grounding` を直接使う |

## 工程の間の決まり

- 縛る値の根拠は、一次情報の記録の項目の識別子で指す。記録の作り方と状態の付け方は `primary-source-grounding` に従い、このプロファイルで定め直さない。
- 実測の値は、一次情報の記録と分けて書く（測った日、道具、測った物、回数）。実測で直した値は、根拠を「実測」にする。
- 安全に関わる値が未確認のままなら、`visual-ok` で採っても「確定ではない」と結果に書き、仮置きで試作に進めるかを `policy-ask` で依頼者が決める。
- 検査に落ちたとき、閾値を緩めて通すかは `policy-ask` で依頼者が決める。担当が黙って緩めない。
- `visual-ok` では、プレビューと、道具の画面で開いた見え方の両方を見せる。開いたときに表示が切れている、視点が合わない、なら `cad-build` に戻す。
- 形を変えたら、`cad-build` の検査をすべてやり直し、`visual-ok` を通し直す。前の試作で確かめた所に及ぶなら、その所を確認の手順に書く。

## 終わり方

人が `visual-ok` で採り（試作するなら `fit-feedback` で採り）、確認の手順に、主な寸法、根拠の所在、未確認の値、組み立て直す命令があれば終わる。未確認の値が残るなら、終わりの報告に一覧で書く。
