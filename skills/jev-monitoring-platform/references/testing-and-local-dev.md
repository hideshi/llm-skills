# 試験方針とローカル再現（監視基盤）

分散構成では、モノリスの E2E 厚盛りより **境界＋契約** を厚くする。

| 層 | 目的 | ローカル Docker との関係 |
| :--- | :--- | :--- |
| 純ロジック Unit | 閾値適用・集計・正規化 | コンテナ不要（言語のテストランナー） |
| 契約／スキーマ | イベント・API・閾値版メタ | コンテナ不要 |
| コンポーネント | Worker 単体＋模せるバインディング | **`templates/local-dev/` の1コンテナが主戦場** |
| 狭い統合 | staging の AE／D1 等へ合成投入 | Docker ローカルの外（または一部のみ） |
| 合成パイプライン E2E | 判定→記録→見える、少数・決定的 | staging 寄り |
| 運用リハーサル | 版切替・再較正・権限 | 低頻度 |
| 本番観察 | SLI／探针 | テストではなく監視 |

## Docker の置き方
- 例: `templates/local-dev/Dockerfile.example` と `docker-compose.example.yml`
- **案件リポにコピーしてから使う**。スキル内の例を本番パスに焼かない。
- 版（Node / Wrangler）は出典付きで更新する。

## 再較正・トリアージとの関係
トリアージには政策版・現行閾値・`datasetVersion`・直近メトリクスの**読み取り共有**が必要、という前提がある。ローカル Docker はその共有面の開発用スタブには使えるが、本番共有面の代替ではない。

**本版スコープ外**: 政策スナップショット共有の詳細契約、および再較正トリアージの業務フロー（誰が・いつ・何を見て較正に入るか）は後段で契約化する。本スキルの中立コア役割表にはまだ載せない。
