# 道具と版の比べ方

[SKILL.md](../../SKILL.md) の手順で使う道具の例と、版の範囲の比べ方。コマンドは例で、入っている道具の版の説明（`--help`）と公式の文書で確かめてから使う。自動で直す・更新するオプションは使わない。

## 確かめた範囲

- 確かめた日: 2026-11-13。確かめた版: 道具は動かしておらず、その日の npm と Composer の audit の公式の文書（最新の版の頁）を読んだ。
- 【資料】と書いた点は、その文書で読んだことで、手元で流してはいない。ほかの道具の行は、公式の文書の所在だけを示し、オプションは照合していない。

## 道具の例

| 対象 | 道具と機械が読める出力の例 | 注意 |
|---|---|---|
| npm のロック | `npm audit --json`【資料】。開発用を除くなら `--omit=dev`【資料】 | 依存の一覧の説明をレジストリへ送る（公式の文書に記載。【資料】）。送ってよい先かを先に確かめる。弱点が見つかると0でない値で終わる（`audit-level` で変わる。【資料】）。最後の「N vulnerabilities」は部品の数で、告知の数ではない。告知の数は告知の識別子で数える |
| Composer のロック | `composer audit --locked --format=json`【資料】。開発用を除くなら `--no-dev`【資料】 | `--locked` は、展開先ではなくロックの中身を点検する【資料】。終了の値は 0（問題なし）と 1（当たる部品があるか、要る部品が無くて失敗）の二つ【資料】。弱点と失敗を終了の値だけで分けられないので、出力も読む |
| pnpm、Yarn のロック | 各道具の audit（公式の文書: https://pnpm.io/cli/audit 、https://yarnpkg.com/cli/npm/audit ） | 未照合。まとめて管理する範囲と、出力の形の違いを確かめる |
| Python | pip-audit（https://github.com/pypa/pip-audit ） | 未照合。依存の解決や導入を伴う使い方は、隔離した環境だけで |
| Go | govulncheck（https://pkg.go.dev/golang.org/x/vuln/cmd/govulncheck ） | 未照合。呼び出しが届くかの判定を補う。解析できない組み立ての条件を「当たらない」にしない |
| 複数の言語のロック | OSV-Scanner（https://google.github.io/osv-scanner/ ） | 未照合。対応する入力だけを読むので、棚卸しと照らす |
| コンテナと OS のパッケージ | イメージの固定の識別子を指定した走査の道具 | 未照合。配布元が修正を取り込んでも上流の版の番号を変えないことがあるので、直ったかはパッケージの変更履歴の告知の番号で判断する |
| 実行環境、DB、Web サーバー | 動いているプロセスの実際の版と、配布元の公式の安全の告知 | 依存のロックだけでは分からない。シェルで見える版と常駐のプロセスの版は食い違いうる |

## 告知の形の読み方

告知の情報の共通の形（OSV の形式、https://ossf.github.io/osv-schema/ 、2026-11-13 に版 1.9.2 の頁を読んだ。【資料】）では、範囲を出来事の並びで表す。

- `introduced`: その版から当たる。
- `fixed`: その版で直った。当たる範囲の外。
- `last_affected`: 公表の時点で当たると分かっている最後の版。その次の版が直った版とは限らない。
- `limit`: 範囲の上限で、直った版の意味ではない。
- `aliases`: 同じ弱点の、別の情報の集まりでの識別子。同じ告知かは、別名か公式の所在で確かめる。題名が似ているだけでまとめない。

## 版の比べ方

1. 生態系の比べ方の決まりの道具を使う（例: npm は semver、Composer は constraint の解析、Python は PEP 440 に沿った道具）。使った道具と版を記録する。文字の比べや、上限に1を足すような手の計算をしない。
2. semver では、同じ数字の版なら、試験的な版（`-alpha` など）は正式な版より前になる（https://semver.org/ 、9 と 11.3。【資料】）。
3. 「今の系列」を案件で決める（今の大きな版、保守中の版）。黙って大きな版を上げた版を最小の候補にしない。
4. 告知ごとに、今の版を含む当たる範囲の境目を取り出し、同じ系列の公開の版を昇順に並べて、今回のすべての告知の範囲に入らない最初の版を候補にする。別の区間で再び当たることがあるので、境目の最大の値だけで決めない。
5. 修正の版が無い、同じ系列に候補が無い、判定できない、を分けて記録する。道具の「直せる」の表示は参考で、全部の告知を避ける最小の版とは別。
6. 最小の候補と、勧められる版は別の欄にする。候補の実行環境の要件と、ほかの依存の制約も書き、入れずに確かめられない点は未確認と書く。
