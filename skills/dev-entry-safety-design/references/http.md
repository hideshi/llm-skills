# HTTP の場合

[SKILL.md](../SKILL.md) の手順を、HTTP で画面やデータを返すアプリに当てはめるときの具体。値の正本は、案件の安全の方針と、各仕様の今の版。ここに書いた値をそのまま正本にしない。

## 応答の見出し

| 守りたいこと | 見出しや設定 | 注意 |
|---|---|---|
| 他のサイトに埋め込ませない | `Content-Security-Policy` の `frame-ancestors`、対応しない環境向けに `X-Frame-Options: DENY` か `SAMEORIGIN` | 読んでよい資源の制限を報告だけの形（`Content-Security-Policy-Report-Only`）で試している間は、その制限では止まらない。埋め込みの拒否が要るなら、強制に移すまで `X-Frame-Options` を残す |
| 内容の種類を推測させない | `X-Content-Type-Options: nosniff` | 応答の `Content-Type` を正しく付けることと組にする |
| 読んでよい資源を制限する | `Content-Security-Policy` | まず `Content-Security-Policy-Report-Only` で違反を集め、落ち着いてから強制に移す（人の承認） |
| 以後は暗号化した通信だけにさせる | `Strict-Transport-Security` | 暗号化した通信で返す環境でだけ意味がある。期間と下位の名前への広げ方は、取り消しにくいので人が決める |
| 版や構成を明かさない | `Server`、`X-Powered-By` を消すか、中身の無い値にする | 走査の道具が古い版の文字列を拾っても、実際に読み込んでいる資源と突き合わせてから問題として扱う |

設定は、応答を出した層に付ける。画面の文書を返す層とデータを返す層が別なら、両方で決める。前段の中継にだけ付けると、手元の環境で確かめ直せない。

## Cookie

| 属性 | 使う場面 |
|---|---|
| `Secure` | セッションの Cookie。暗号化した通信でだけ送らせる |
| `HttpOnly` | セッションの Cookie。画面のスクリプトから読ませない |
| `SameSite` | 別のサイトからの要求に Cookie を付けさせない補助。出どころの確かめの代わりにしない |

画面のスクリプトが読む方式の、出どころの確かめの値を入れた Cookie には `HttpOnly` を付けない（読めなくなる）。この方式を変えるのは人の承認が要る。

## 状態を変える要求の出どころ

- Cookie でログインを保つなら、状態を変える要求（`POST` など）は、使っている枠組みの標準の確かめを使う。
- `SameSite` だけに置き換えるなら、その判断を設計の判断に書く。

## 別の出どころからの呼び出し

- 許す出どころを列挙する。資格情報を付けた呼び出しを、すべての出どころに許さない。
- 開発用の環境での全部を許す設定を、本番の設定に持ち込まない。

## 外から読む資源

- 外のサーバーから読むスクリプトとスタイルには、`integrity` 属性と `crossorigin` を付ける。または、同じ出どころに移す。どちらもしないなら、使う目的と許す先を例外として記録する。
- 中身の確かめは、別の出どころの資源では CORS が要る。
- 使っていない読み込みの宣言は消す。接続の準備だけの宣言（`preconnect`）には中身の確かめは要らない。

## 確かめ方

- 契約の試験: 見出しがある、許さない読み込み先がソースに無い、`integrity` がある、他人の識別子で `403` か `404` が返る。値が固定できるものだけを試験にする。
- 機能の回帰: 資源を消したり置き換えたりした画面が、今までどおり値を受け付ける。見えるだけでは足りない。
- 普通の応答を見るだけの点検で分かるのは、見出し、Cookie の属性、中身の確かめの有無、版の文字列まで。認可、業務の手順、書いた後に別の画面で出る問題、踏んでいない窓口は、それで安全とは読まない。
