# 判断入力の点検と感度測定

正解が一意でない判断、感度測定、反復の揺れを扱う共通手順。較正の合否は [jev-calibration](../../jev-calibration/SKILL.md)、歴史固有の根拠・人物の認識・人による評価は[歴史的文脈を含む判断の設計と評価](historical-judgment-evaluation.md)で扱う。史料の一例や実験者の予想を唯一の正解にせず、評価資料を固定しただけで freeze 済みとしない。探索の安定や期待方向への変化だけで `VALIDATED` や `datasetStatus: frozen` を付与しない。

## 問い合わせ前の入力点検

- 毎回、判断役へ送る全文（問い・criteria・state とそのテンプレート）を点検し、正解・比較条件名・実験の意図が漏れていないか確認する。業務上必要な基準を渡すことと期待する答えを書き込むことを区別し、基準に従っただけで「解釈した」と主張しない。
- 人物判断では、本人が判断時点で知らない情報が混ざっていないか確認する。
- 全文の点検と全文の保存は別の義務として扱う。保存は案件の保持・プライバシー方針に従い、本文を保存しない場合も版・参照先など入力を特定できる記録を残す。
- 予想と違う結果の後に入力を直して測り直すときは、元の結果を残し、修正と再測定を一つの追加探索として記録する。さらに改訂する場合も別の探索として残し、期待する結果までの試行を一回の確証試験にまとめない。期待に合わせて閾値だけを動かさない。

## 反復と条件比較の事前固定

- 結果を見る前に、反復回数、比較する組、測る確率、集計方法、閾値の近くとみなす幅、判定基準を決める。値は案件で定め、固定の回数・幅を一般則にしない。
- 前提・入力・問い・選択肢・期待方向と根拠（根拠不足を含む）を事前記録する。疎通後は同一入力の反復、条件差、同義のつもりの言い換え、必要に応じ情報配置・選択肢順を比較する。言い換えの等価性は別途確認する。
- 条件の実行順を入れ替え、各値・実行順・要求したモデルの別名と応答の実際のモデル名・時刻を記録する。API 出力の反復と、固定した分布からの抽選の反復を分ける。
- 範囲の重なりだけで差の有無を決めず、「基準未満」と「同等」を混同しない。言い換えの派生文は元の事例と同じデータ分割に入れる。
- ラベルの意味、criteria の判定境界、Score のアンカーが変わったら評価セットを再 freeze する。問い文・criteria・state テンプレート（人物文を含む）の言い換えは自動で再 freeze を求めないが、`questionRev` を更新し、再推論とゲート再測定を省略しない。較正対象なら `validationStatus: PENDING` に戻す（[共有語彙 §3](jev-lifecycle-status.md#3-差し戻し矢印)）。フォーマットの固定と問いの版管理は[設計パターン §2](../../jev-logic-architect/references/jev-design-patterns.md#2-問いinstructions--criteria--stateの設計)に従う。
- 問いごとに「何が分かったら止めるか」と問い合わせ件数・費用の上限を事前に決め、実行前に残量を確認する。費用の見積もりは[単価の参照](../../jev-candidate-detector/references/cost-estimation-reference.md)を取り直して行う。上限は誤った大量呼び出しの歯止めでもある。

## 分布の読み方

分布の集中の度合い、正答率、確率の較正、現実の行動頻度を区別する。平坦な分布は、業務分類では基準の区別不能を疑う手掛かりになるが、正解が一意でない判断では複数の行動がどれも妥当な場合もある。

### confidence と閾値

[公式 Confidence 文書](https://docs.typesafe.ai/confidence)（確認日: 2026-11-09、掲載日・API 版の記載なし）に基づく。

- Choice は `confidence = (p_max - 1/n) / (1 - 1/n)`。選択肢数が固定なら最大確率との変換関係であり、両方をゲートにしても独立の証拠にならない。選択肢数の増加で必ず confidence が下がるとはいえない。
- Score は最頻レベルからの確率加重距離を、一様分布の中央からの平均距離で規格化し、`max(0, 1 - 距離 / 規格化距離)` とする。隣接レベルへの分散と遠いレベルへの分散を区別し、Choice と同じ式を使わない。Noul に独立した confidence はない。
- confidence は正答確率ではない。最大確率も実際の正解率と同一視せず、[設計パターン §5](../../jev-logic-architect/references/jev-design-patterns.md#5-実証的な閾値threshold選定プロセス)の較正確認を優先する。
- **正解ラベルのある業務分類で判断を自動確定する場合**、Choice は行動する選択肢の確率に閾値を置き、評価データと誤分類コストで検証する。公式ページのコード例は confidence で分岐し、この本文の推奨と食い違うため、そのまま転用しない。
- API の `choice` と、外部で確率から抽選して選んだ行動を区別する。人物の行動を抽選する模擬用途には、この自動確定の閾値による一律の停止・縮退を求めない。

## 記録と限界

- 送信入力を特定できる版・参照先、生応答、実際のモデル、時刻・所要時間、エラー、取得できる使用量を案件側へ記録する。本文の保存範囲は前述の方針に従う。エラーや未問い合わせを架空の分布で埋めない。
- 条件を一つずつ変えた確率差は、モデル出力の感度であり、内部の理由や現実の因果ではない。複数条件の同時改訂を単独要因の効果や厳密な A/B の証拠にしない。追加仮説は元の計画と分ける。
- 観察数値や効果の向きを一般則にしない。事例を引用する場合は題材・モデル版・回数・限界と報告書の節を指定する。確認できない情報は推測しない。
- 終了時は、問いが解明されたのか、事前に決めた数値の条件に達したのか、未確定のまま上限等で打ち切ったのかを区別して記録する。
