# 回帰の基準を固める

既存の処理を変える前に、今の動きを期待値にした検証点を作り、改修前の版で通しておく。改修の後にこの基準が落ちたら、意図しない変化として扱う。今の動きが正しいかは問わない。正しくない動きも、区分を付けて記録したうえで基準に含める。

## 入力

| 型 | 必須 | 使い方 |
|---|---|---|
| 現状の振る舞いの記録 | 条件付き（新しく固めるとき必須） | 検証点の期待値の出どころ |
| 回帰の基準 | 条件付き（更新するとき必須） | 更新する前の検証点と区分 |
| 問題台帳 | 任意 | 問題に関わる検証点に、区分と問題の識別子を付ける |
| 業務規則の一覧 | 任意 | 規則に関わる検証点に、規則の識別子を付ける。仮説の規則は、期待値の根拠にしない |
| 是正の対応表 | 任意 | 更新するとき、変えると決めた動きを確かめる |
| 完了条件の一覧 | 任意 | 更新するとき、機能の変更で決まった求める動きを確かめる |
| 変更の事実 | 任意 | 更新するとき、何が変わったかを確かめる |

型の中身は [型の一覧](../dev-shared/references/artifact-types.md) を見る。

- 新しく固めるのに現状の振る舞いの記録が無いときは、固めずに止め、固める範囲の記録を求める。記録の無い期待値で基準を作らない。
- 更新するのに、変える根拠（是正の対応表、完了条件の一覧、依頼側の回答）が無い検証点は、期待値を変えずに回帰として報告する。

## 出力

| 型 | 中身の補足 |
|---|---|
| 回帰の基準 | 検証点ごとの期待値・区分・置いた層・本物と疑似の境界・繰り返しと誤りの注入の結果・対象の版 |
| 検証の記録 | 改修前の版での実行、更新後の実行、観察だけの実行の記録 |

## 使わない場面

- 今の動きを調べて記録する（入力の記録を作る、別の仕事）。
- 不具合を直す。基準を通すために動きを直さない。
- 改修後の求める動きを試験する。求める動きの試験は、基準とは別に作る。

## 検証点の区分

| 区分 | 意味 | 改修の後に期待値が変わったとき |
|---|---|---|
| 保持 | 改修の後も変わってはいけない | 回帰として扱い、改修を見直す |
| 変更予定 | 問題台帳や是正の方針で、変えると決まっている | 決めた動きと一致するかを確かめ、期待値を更新する |
| 回答待ち | 依頼側の判断や事実確認を待っている | 期待値を変えず、落ちたことを記録する。基準の合否からは外して先へ進み、回答が出たら区分を決め直す |

区分の無い検証点の期待値が変わったら、回帰として扱う。

## 手順

### 1. 検証点を選ぶ

- 共有の処理を変えるなら、それを使う側すべての動きを検証点に含める。
- どの層で確かめるか（単体、処理を通す試験、画面を通す試験など）は、影響の大きさ、再現のしやすさ、下の層で捕まえられる範囲、維持の手間で選ぶ。すべてを画面の試験にしない。
- 時刻、外部への送信、乱数のように揺れる要素は、固定するか捕まえる。

### 2. 改修前の版で通す

- 改修前の版で、今の動きを期待値にして通す。改修後の理想を期待する試験とは分けて置く。
- 本番のデータや資格情報を使わず、隔離した環境で動かす。疑似にした外部の仕組みの限界を書く。

### 3. 基準の確かさを確かめる

- 初期の状態から3回以上続けて通ること。
- 動きをわざと壊すと、対応する検証点が落ちること。壊したものを戻すと、元どおり通ること。戻した後に、作業ツリーの差分が残っていないことも確かめる。
- 落ちない検証点は、何も確かめていない疑いがある。期待値か観察の仕方を直す。

### 4. 疑いが残るとき

- 正誤を判定しない、観察だけの手順で、起きた事実を記録する。
- 道具の失敗と、システムの成功・拒否を混ぜない。
- 同時に動かしたことを確かめたいときは、実際に重なったことを記録し、順に動かした結果と比べる。
- 確定した事実だけを、現状の振る舞いの記録と問題台帳に戻す。直すのは別の工程。

### 5. 基準を更新するとき

- 期待値を変えてよいのは、区分が「変更予定」で、変える動きが是正の対応表、完了条件の一覧、依頼側の回答のどれかで決まっている検証点だけ。
- 更新するときは、区分、関係する問題の識別子、根拠を検証点に書く。黙って期待値を変えない。
- 新しい事実が出たら、検証点が確かめている内容と、主張している内容が合っているかを見直す。確定した不具合をすべて画面の試験に足さない。

手順の根拠と、先行の手法から変えたところは [根拠と変えたところ](references/grounding.md) を見る。

## 終了条件

新しく固めたとき:

- 範囲のすべての検証点に、期待値、区分、置いた層がある。
- 改修前の版で、3回以上続けて通った記録がある。
- 壊すと落ち、戻すと通ることを、検証点ごとか、まとまりごとに確かめた記録がある。
- 疑似にした部分と、その限界が書かれている。

更新したとき:

- 期待値を変えたすべての検証点に、区分、関係する問題の識別子、根拠がある。
- 根拠の無い変化は、期待値を変えずに回帰として報告されている。
- 更新後の版で基準を通した記録がある（回答待ちで外した検証点は、その一覧がある）。
