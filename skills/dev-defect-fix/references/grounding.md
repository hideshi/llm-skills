# 根拠と変えたところ

報告された不具合や確定した問題を再現確認から結果表の報告まで是正する手順が、どの先行の手法に基づき、どこを変え、どこが独自の判断かを書く。手順そのものは SKILL.md が正本で、ここは読む人が元の考え方をたどるための別紙。

- 確かめた水準: 「原典を読んだ」「書誌と二次資料で確かめた」「未確認」

## 先行の手法

| 手順の箇所 | 手法 | 出典 | 確かめた水準 | 同じところ | 変えた・足したところ |
|---|---|---|---|---|---|
| 1. 受付・2. 現実を確かめる | 体系的デバッグ（Systematic / Scientific Debugging） | Andreas Zeller『Why Programs Fail: A Guide to Systematic Debugging』第2版、Morgan Kaufmann、2009、第2章「Tracking Problems」・第4章「Reproducing Problems」・第6章「Scientific Debugging」 | 書誌と二次資料で確かめた（本文は未読） | 症状・期待・環境を整理して事実を追跡し、同じ条件で再現させてから仮説を立てて確かめる | 観測の経路の切り分け、報告日と修正コミット日の前後比較、「再現しない」と言うための3要件（同経路・環境差の仮説・「既に直っている」と「調べ足りない」の区別）を足した |
| 4. 直す（症状を捕まえる試験と回帰試験化） | 再現テスト先行と回帰テスト化 | Kent Beck『Test-Driven Development: By Example』Addison-Wesley、2002。Michael Feathers『Working Effectively with Legacy Code』Prentice Hall、2004 | 書誌と二次資料で確かめた（本文は未読） | 症状を捕まえる落ちる試験を先に書いてから最小の修正を行い、その試験を回帰防止として残す | 報告項目だけでなく範囲の表・落とし穴・望ましくない出力が無いことまで試験に含め、文書修正と回帰基準との突き合わせまでを一続きにした |

## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 方針を5段階の検討順（局所固定 → 共有の仕組み寄せ → 横断設定変更 → 文書・配備フォローのみ → 直っていることを確かめ、保証を強める）で選び、選ばなかった案も1行ずつ残す | 影響範囲の狭い安全なやり方を優先しつつ、別のやり方を採らなかった判断根拠を後から追えるようにするため | 検討順に沿って選んだ方針で後から広範囲変更へ見直した件数と、不採用理由が再検討で役立った割合を問題台帳・是正の対応表で比べ、5段階順を見直す |
| 4つの判断（意図した差の扱い、横断設定への切り替え、本番データ・外部設定の変更、同じ形の箇所への同時拡大）は人が決める関門にする | 局所の修正のつもりが仕様変更や広範囲の波及・本番変更へ無断で広がるのを防ぐため | 無断拡大や仕様取り違えによる手戻り件数と人関門で設計が変わった割合を記録し、4関門の境界を見直す |
| 「直したと言える状態」7項目と結果表の書式（同じ番号対応・実測値の記載・「決めたとおり」だけの記載禁止・結論件数の合計一致・直前版での再実行）を定める | 「試験が通った」「レビューに通った」という作業状態の報告で、決めたとおり直った証明を代用させないため | 結果表を通った後に再発や仕様不整合が発覚した件数を実測欄の有無と比べ、7項目の必要条件を見直す |
| 同じ形の箇所の探索に打ち止めの目安（形ごとに検索2本、表は10行まで。探索を短くする条件では検索1本）と振分けを定め、繰り返し出る形は試験や機械検査で止められないかを1行検討する | 横展開の調査が際限なく膨らむのを防ぎ、見つけた候補の扱いと再発防止の仕組み化を漏らさないため | 検索打ち止め外で見つかった同種再発件数と仕組み化で同種不具合が減った推移を記録し、目安と振り分け基準を見直す |
| 再現実行を隔離した環境で行い、本番データと資格情報を使わず、外部への送信を捕まえる | 不具合再現の試行で本番データの破壊や顧客への誤送信が起きるのを防ぐため | 再現時の外部誤送信・本番影響件数と隔離差による誤判定件数を記録し、隔離手順を見直す |
| 今回直さない穴や別環境の未確認を「方針外の課題の記録」へ担当・追跡先・回収の時期・成功条件つきで移し、古いメモを片づける | 条件付き完了や残存リスクが放置されて消えるのを防ぐため | 方針外の課題の記録へ移した残存リスクが回収期限を過ぎて放置・再発した件数と、後から不要として取り下げられた件数を是正の対応表で比べ、4要素の定義を見直す |
| 直さないと決めた行も結果表の全行数から外さず、確かめていない行に数える | 直さない行を分母から外すと、結論の「全行のうち」が方針表と合わなくなり、残した穴が結論から見えなくなるため | 承認の後に、結論の行数が方針表の行数と合わなかった件数と、直さない行が後で問題として戻ってきた件数を記録し、数え方を見直す |
