# 規則を基準にした比べ方

公的な規則（法令、通達、公表の基準）を物差しにして、システムの今の姿と比べ、要件を起こすときの手順。

## 物差しを外に置く

- 今のシステムの作りから要件を起こさない。物差しは規則の側に置く。
- 人の説明（担当者の理解）は物差しに入れず、確かめる対象にする。

## 範囲と工程

- 比べるシステムと、それぞれの「今」の出どころ（今の動きの記録、設定、文書）を決める。
- 工程ごとに、「規則で決まる」「慣行」「未確認」を分ける。

## 要件の種類の型

規則が求めることを、型に分けて探す。型ごとに、探したか、該当なしかを記録する。型は領域に合わせて選ぶ。次は例。

誰が義務を負うか、何が対象か、届け出や報告の事項、期限、金額や数量の決め方と端数、例外、違反したときの扱い、記録と保存、禁止されていること、適用の単位（件ごとか、まとめてか）。

## 比較の表

| 列 | 書くこと |
|---|---|
| 基準 | 一次情報の記録の項目の識別子（条文は写さない） |
| 規則の求めること | 要約 |
| 今の姿 | システムごと。経路ごとに値が違えば分ける |
| 差の種類 | 下の表 |
| 連鎖 | この行の答えで決まるほかの行 |

- 設定の既定値を「固定」と書かない。
- 適用の単位のずれ（件ごとか、まとめてか）を並べて書く。

## 差の種類

| 種類 | 扱い |
|---|---|
| 規則と合わない | 直す差として問題台帳へ |
| 関係者の決定と規則の読みが合わない | 決定を書き換えず、決めた人に返す（確認事項） |
| 決まっていない | 確認事項 |
| 確かめていない | 事実（今の動きやデータ）なら問題台帳の事実確認、関係者の意向なら確認事項 |
| システムの間で食い違う | 問題台帳。責任を持つシステムを書く |

## まとめ方

- 差の大きさの定義を先に決める。
- 確かめることを相手ごとに冒頭に並べ、仕様の判断と事実の確認を分ける。
- 表に入れていないもの（範囲外にしたもの）を書く。
