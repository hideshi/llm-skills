# 完了条件の一覧の例

型: 完了条件の一覧
形の一例。正本は型の一覧の欄。形式・節名・置き場所は任意で、案件に既に形があればその形に従う。値はすべて作り物。

題材は、確定した請求書の明細を直せないようにする変更。道は、規模の判定に従う。この例の識別子は、同じ題材のほかの単位の例（業務規則の一覧、テストケース表、画面の設計など）と同じものを使う。

## 要件

| 欄 | 中身 |
|---|---|
| 識別子 | `REQ-7` |
| 目的 | 取引先に送った請求書と、社内の記録が食い違わないようにする |
| 利用者 | 経理の担当 |
| 入力情報 | 請求書の状態、明細の一覧と合計 |
| 判断 | なし（確定した請求書の明細を直すかどうかを、利用者に選ばせない） |
| 適用する画面 | 既存の画面「請求書の詳細」 |
| やらないこと | 確定した請求書を取り消して作り直すこと（別の要件で扱う。取り消してよい人が、未確定の規則 `BR-15` に頼るため） |

目的とやらないことは、単位の本文が要件ごとに求める項目（型の欄の「要件」の中身として書いた）。

## 受入条件

| 識別子 | 属する要件 | 確かめる業務規則 | 受入条件 |
|---|---|---|---|
| `AC-21` | `REQ-7` | `BR-12` | 確定した請求書に明細を追加・更新・削除しようとすると拒まれ、明細と合計は変わらない |
| `AC-22` | `REQ-7` | `BR-12` | 確定した請求書の詳細の画面では、明細の編集の操作が使えず、確定済みのため変えられないことが画面の文で分かる |
| `AC-23` | `REQ-7` | `BR-12` | 下書きの請求書の明細は、これまでどおり追加・更新・削除できる |

どの受入条件も、修正を知らない人が、操作と結果を見て合否を決められる形で書いた（`AC-23` は、変えないことの確かめ）。

テストを先に書かない範囲: 無い。廃止した項目: 無い。
