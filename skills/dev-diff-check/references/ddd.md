# DDD で組むとき

DDD の戦術の形（集約、値オブジェクト、ドメインサービス、リポジトリ）で組む案件で、差分の点検に足す観点。構成の方針か設計の判断がこの形を採ると決めている案件でだけ使い、フォルダの名前などから推し量って当てはめない。ガードを置く場所の正本は、業務規則の一覧の「所有」。下の表と所有が違う所を指すときは、所有に従う。

| 観点 | 見ること |
|---|---|
| 集約の内側のガード | 一つのまとまりの中で必ず成り立つ規則（業務規則の種類が「不変条件」のもの）のガードが、まとまりの内側（集約か値オブジェクト）にあるか。手順を調整する側にしか無いのは、置き場所の違反 |
| まとまりをまたぐ規則 | 複数のまとまりにまたがる規則が、ドメインサービスか、データベースの制約か、設計の判断が決めた所にあるか |
| まとまりの単位での保存 | まとまりの一部だけを保存して、規則を飛ばしていないか。読むだけの一覧は別の形でよい |
| 値オブジェクト | 値の検証が、値を作る所に集まっているか。同じ検証が呼び出し側に散っていないか |
| リポジトリ | 保存の仕組みの型（問い合わせの組み立て、接続）が、業務の判断の側に漏れていないか |
| イベント | イベントの名前が、起きた事実を業務の言葉の過去形で表しているか。出す所が、きっかけの遷移と同じ所か |
