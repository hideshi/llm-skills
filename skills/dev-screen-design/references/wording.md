# 文言の決まり

画面の文言を決めるときの決まり。案件に文言の決まりがあれば、そちらに従う。

## 語の出どころ

- 管理面は、ドメインモデルの用語を第一の候補にする。同じものに2つの名前を使わない。
- 公開面は、利用者の言葉を第一の候補にする。業務の用語と画面の言葉が違うときは、対応の表を共通仕様に1か所だけ置き、人が採る。
- 画面の部品の名前（ダイアログ、横のパネルなど）を、利用者に見える文言や読み上げの名前に出さない。
- 状態の表示に内部のコードを出さない。区分の値は、表示の名前で出す。運用者にコードを見せる必要があれば、主な表示ではなく補助の表示にする。
- 文言の動詞と状態の名前が、どの管理するもの・出来事のことかを確かめる。違うものの出来事を1つの文に混ぜない。

## 文の型

| 種類 | 書き方 |
|---|---|
| 成功 | 何が終わったか（自然な言い方を優先する） |
| エラー | 何が起きたかと、次にとる行動 |
| 確かめ | 影響の範囲（件数、取り消せないこと） |
| 入力の検証 | どの項目が、どんな条件を満たす必要があるか |
| 利用者への案内 | 「〜してください」（利用者がすること）。「〜します」はシステムがすることだけに使う |

- 取り消せない操作でも、威圧する語を使わず、何が起きるかを正確な動詞で書く。影響は確かめのダイアログで見せる。
- 複数の操作がある画面は、操作ごとの文言を表にして先に決める。
- エラーの文言は、エラーの設計の判断を指す。ここで新しく作らない。

## 出さないもの

- 内部の識別子、規則の番号、物理の名前、技術の語（同期、トランザクションなど）。
- 作業の都合の分類の名前。
- デモや試作のための注記（「サンプル」など）。
