# 文言の決まり

画面の文言を決めるときの決まり。案件に文言の決まりがあれば、そちらに従う。読む人と語の一覧、呼び名、内部の語、異常な状態の書き方、読み直しの確かめ方の基準は、[型の一覧](../../dev-shared/references/artifact-types.md)の「利用者向けの文言の書き方」にある。ここには、画面に固有の決まりだけを書く。

## 語の出どころ

- 管理面も公開面も、その画面を読む人（画面一覧の利用者）の語を第一の候補にする。管理面の読む人が業務の専門家なら、ドメインモデルの用語がその人の語になる。
- 業務の用語と画面の言葉が違うときは、対応の表を共通仕様に1か所だけ置き、人が採る（案件の文言の決まりが続けて使う文書にあれば、そちらを指す）。
- 画面の部品の名前（ダイアログ、横のパネルなど）を、利用者に見える文言や読み上げの名前に出さない。
- 状態の表示に内部のコードを出さない。区分の値は、表示の名前で出す。運用者にコードを見せる必要があれば、主な表示ではなく補助の表示にする。
- 文言の動詞と状態の名前が、どの管理するもの・出来事のことかを確かめる。違うものの出来事を1つの文に混ぜない。

## エラーの文言との境目

- エラーの一覧に行がある文言（エラーの種類ごとの利用者向けの文言）は、エラーの設計の判断が正本。画面では指すだけにし、新しく作らない。読み直しの結果も、エラーの判断の側に書く。
- 画面で書いて確かめるのは、状態の説明（失敗や期限切れ、結果が分からない状態にある間の画面の文、空の状態）、操作の呼び名、エラーの後の次の行動の見せ方。

## 文の型

| 種類 | 書き方 |
|---|---|
| 成功 | 何が終わったか（自然な言い方を優先する） |
| エラー | 何が起きたかと、次にとる行動（文言はエラーの設計の判断を指す） |
| 状態の説明（失敗した、結果が分からない、期限を過ぎた、止められている状態にある間） | 今どういう状態か、もう一度できるか（いつまで）、もう一度やったら何が起きるか（型の一覧の「利用者向けの文言の書き方」） |
| 確かめ | 影響の範囲（件数、取り消せないこと） |
| 入力の検証 | どの項目が、どんな条件を満たす必要があるか |
| 利用者への案内 | 「〜してください」（利用者がすること）。「〜します」はシステムがすることだけに使う |

- 取り消せない操作でも、威圧する語を使わず、何が起きるかを正確な動詞で書く。影響は確かめのダイアログで見せる。
- 複数の操作がある画面は、操作ごとの文言を表にして先に決める。

## 出さないもの

- 型の一覧の「利用者向けの文言の書き方」で疑う語に挙げた、内部の仕組みの語（読む人の語でない限り）。
- 作業の都合の分類の名前。
- デモや試作のための注記（「サンプル」など）。

## 読み直して確かめる

状態の説明の文と、新しく決めた操作の呼び名は、型の一覧の「利用者向けの文言の書き方」のとおりに、仕組みを知らない読み手に読ませて確かめる。結果は、画面ごとの仕様の文言の欄に、その文の横に添える。
