# 画面の導き方

画面の候補を出し、まとめ、流れを決めるときの手がかり。どれも候補を出すための目安で、要件に結びつかない画面は作らない。

## 管理面

| 出どころ | 画面の候補 |
|---|---|
| 管理するもの（件数が多い） | 一覧と検索 |
| 管理するもの（属性が多い、関係を見たい） | 詳細 |
| 管理するものを作る・直す | 入力の画面（作ると直すで項目が同じなら1つにまとめる） |
| 管理するものを消す | 確かめのダイアログ（影響の範囲を見せる） |
| 単純な状態の変更（承認する、取り消す） | 詳細の中の操作と、確かめのダイアログ |
| 追加の入力が要る状態の変更（差し戻す理由など） | そのタスクの画面 |
| 順番のある複数の段（2〜5段） | 段を追う画面。最後の段で内容を見せて確かめる |
| 人の承認を要する規則 | 承認待ちの一覧と、承認の画面 |
| 利用者ごとの見たい情報が違う | 利用者ごとの入口（同じデータで操作だけが違うなら、1画面で出し分ける） |

まとめる・省く目安:

- 件数が常に少ないものは、一覧を省いて親の詳細に入れる。
- 単独で開く必要の無い子は、親の詳細の中に置く。
- 省いた画面は、画面一覧の「作らない画面」に理由と一緒に残す。

## 公開面

管理するもの × 操作からは導かない。流れの段から導く。

| 段 | 画面の候補 |
|---|---|
| 訴求 | 入口のページ |
| 入力 | 入力の画面（要件の主な流れから） |
| 結果 | 結果の画面 |
| 問い合わせ | 問い合わせや申し込みの画面 |
| 完了 | 完了の画面 |

段は省いたりまとめたりしてよい。3段以内なら、段の表示（いまどこか）で足りることが多い。

## 開き方の選び方

デザインシステムの判断に選ぶ基準があれば、それに従う。下は基準が無いときの目安。

| 開き方 | 向いている場面 |
|---|---|
| ページ | 項目が多い、複数の段がある、戻れることが大事 |
| ダイアログ | 確かめ、少ない項目の入力 |
| 横のパネル | 一覧を見たまま詳細を見る |
| その場で編集 | 1〜2項目の直し |

横のパネルは、一覧に重ねる形を既定にし、一覧を押し縮める形は、常に2つを並べて見る必要があるときだけにする。どちらにしたかと理由を書く。

## 一覧の画面で決めること

- データの範囲（本人／組織／横断）。横断なら、行がどの組織のものかが分かる列を置く。行ごとに違う属性は、見出しの共通の表示ではなく、行に出す。
- 絞り込みと並べ替えの項目は、要件の入力情報から取る。表示に出る状態（「未設定」のような組み合わせの状態を含む）は、すべて絞り込みでも選べるようにする。
- 一括の操作では、対象にできない行も見た目をそろえ（選べない形にして）、理由が分かるようにする。
- 行の中の操作が多い（3つ以上）ときは、詳細やメニューに移す。
