# 業務規則から画面の制御へ

業務規則を、画面でどう表すかの置き換え。画面の制御は使いやすさのためのもので、規則を守るのはサーバー側。画面で隠しても、押せなくしても、守ったことにはならない。

## 制御の4つ

| 制御 | 使う場面 | 理由の見せ方 |
|---|---|---|
| 不可 | 今の状態では操作できないが、操作があることは知らせたい | 押せない操作の近くに、文字で理由（上に乗った時だけ出す形にしない） |
| 警告 | 操作できるが、規則の境目に近い、または結果に注意が要る | 入力の近くに、何が起きるか |
| 確認 | 取り消せない、影響が広い操作 | 確かめのダイアログで、影響の範囲（件数、取り消せないこと） |
| 非表示 | その利用者には関係がない、または存在を知らせてはいけない | 見せない。存在を知らせないことは、認可の判断の決まりに従う |

## 置き換えの例

| 規則の種類 | 画面の制御の例 |
|---|---|
| 状態によって直せない | 直す操作を不可にするか、読むだけの表示にする |
| 一意でなければならない | 入力の後に重なりを確かめ、重なりを知らせる |
| 値の範囲 | 入力の検証と、範囲の表示 |
| 関係する2つの値（開始と終了など） | 片方を変えたら、もう片方の範囲も変える。違反したら両方を示す |
| 確定した後は変えない | 読むだけの表示 |
| ほかから使われているので消せない | 消す操作を不可にし、理由を添える |
| 制限の段が複数ある | 段ごとに画面の状態と操作の名前を変える（「直す（終了日だけ）」） |

## 気を付けること

- 状態の機械が2つ以上あるときは、1つの列や1つの表示に混ぜない。どの状態の機械の値かを書く。
- 今の状態から移れる先の操作だけを出す。移れない先の操作は、理由を伝える必要があるときだけ不可で出す。
- 違う経路で得た状態をまとめて数えるときは、経路の違いが分かる表示にする。
- 規則が変わったら、表示の名前、理由の文、不可の条件を一緒に直す。
- 規則の説明を画面の本文に埋めない。画面の名前、表示、不可だけでタスクを終えられるかで見る。
- 日数を足して日付を自動で入れる操作は、締め日のような区切りとの整合を確かめる。確かめられなければ、自動で入れない。
- 規則の識別子は、画面の設計の制御の行に書く。画面に出す文言には書かない。
