# axe-core の場合

ルールで調べる道具の一つ、axe-core を使うときの読み替え。【資料】は資料に書かれた事実（取得日は [根拠と変えたところ](../grounding.md)）、【判断】はこの単位の決まり。

## 結果の種類

- 【資料】結果は4つの並び: `passes`（ルールに通った要素）、`violations`（ルールに落ちた要素）、`incomplete`（「要確認」。判定を打ち切り、さらに確かめが要る）、`inapplicable`（当てはまる内容が無く、走らなかったルール）。
- 【判断】4つともそのまま道具の指摘の表に残す。実行の誤り（走らせる途中の失敗）も別に残す。
- 【判断】`passes` と、`violations` が空なことは、基準の合格ではない。`inapplicable` は、基準の「該当なし」ではない（ルールが見る形が無かっただけ）。
- 【判断】`incomplete` は、道具の指摘の仕分けで「要確認」にし、担当の操作か人の手順で判定する。放っておかない。

## どのルールが走るか

- 【資料】API.md は、既定では `experimental` の印の付いたルール以外を全部走らせる、と書く。一方 rule-descriptions.md は、WCAG 2.2 のルール、AAA のルール、実験中のルール、廃止のルールの4つの群を既定で無効とする。
- 【判断】資料の中で書き方がずれているので、流した版で、ルールごとの有効・無効を実際に確かめて（ルールの一覧を取る API で）検証の記録に書く。
- 【資料】`runOnly` で、名前か印（タグ）でルールを絞れる。WCAG 2.0 の A と AA を走らせるなら `wcag2a` と `wcag2aa` の両方を指す。ほかに `wcag21a`、`wcag21aa`、`wcag22aa`、`best-practice` などの印がある。
- 【資料】WCAG 2.2 のルール（`target-size`。2.5.8 に当たる）は、既定で無効。資料は「WCAG 2.2 が広く採られ、求められるまで」無効とする、と書いている。
- 【判断】目標が WCAG 2.2 の AA なら、`target-size` を有効にしたかを検証の記録に書く。無効のまま流したなら、2.5.8 は自動では見ていないと書く。
- 【判断】`best-practice` の印のルールの違反は、WCAG の違反として数えない。所見に残すなら、根拠の別を「よい慣行」と書く。
- 【判断】流したときの axe-core の版と、絞った印やルールを、検証の記録に書く。版が変わるとルールが変わるため。

## 調べられないもの

- 【資料】閉じたメニューや開いていないダイアログのような、隠れた領域は調べない。調べるには、その領域を開いてから流し直す。
- 【判断】範囲の表の状態ごとに、その状態を開いてから流す。開けなかった状態は、自動では見ていないと書く。

## 作者の主張

- 【資料】作者は README で、誤検知はゼロ（不具合を除く）と、WCAG の問題の平均57%を自動で見つけられる、と述べている。
- 【判断】どちらも作者の主張として扱い、点検の範囲や判定の根拠にしない。自動で見つからなかったことを、残りの問題が少ない根拠にしない。

## 部品カタログとの関係

部品カタログ（Storybook など）の点検の設定は、デザインシステムの判断の道具の資料が受け持つ。ここは、組み上げた画面を流すときと、カタログで流した結果を受けて読むときの扱い。

- 【判断】カタログの結果も、上の「結果の種類」と同じく4つの並びで受けて、道具の指摘の表に部品×状態の行として残す。
- 【判断】カタログで違反を警告に留める設定のとき、カタログの試験が通ったことは、違反が無かったことではない。設定の値は検証の記録で、その値の意味はカタログの道具の公式の資料で確かめる。結果の並びから読み、並びが記録に無ければ、カタログでは見ていないとして扱う。
- 【判断】カタログで通った部品も、画面の中の組み合わせ（ラベルの結びつき、順序、知らせ）では落ちうるので、画面で流し直す。
