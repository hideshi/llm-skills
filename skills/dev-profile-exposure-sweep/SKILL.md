# 今の状態の安全の点検

今動いているシステムの入口と応答を点検し、どこまで見たか、何が問題か、人がどう決めたかを残す組み合わせ。直す作業はこの組み合わせに含めず、問題台帳を原典にして別の組み合わせとして起こす。各工程の中身は単位に任せ、ここでは順序、引き渡す型、振り分けだけを決める。

## 工程

| 識別子 | 工程 | 単位 | 必須 | 受け取る型 | 渡す型 |
|---|---|---|---|---|---|
| `intake` | 受付 | （人） | 必須 | — | 改修の範囲 |
| `entry-check` | 点検する | `dev-entry-safety-check`、`dev-advisory-check`（使っている部品の告知も見ると決めたとき） | 必須 | 改修の範囲、原典の参照、安全の点検の記録、設計の判断 | 安全の点検の記録、問題台帳、検証の記録 |
| `triage-ask` | 人が決める | （人） | 条件付き（問題がある行か、人の判断が要る行がある） | 問題台帳、安全の点検の記録 | 問題台帳、方針外の課題の記録 |
| `final-ok` | 最終確認 | （人） | 必須 | 安全の点検の記録、問題台帳、方針外の課題の記録 | — |

型の中身は [型の一覧](../dev-shared/references/artifact-types.md) を見る。「原典の参照」は、この組み合わせの外（要求を送ってよい相手の許可の記録、案件の安全の方針、走査の道具の結果）から受け取る。前回の安全の点検の記録と、応答と入口の安全の設計の判断も、外から受け取る。

外から受け取る型: 原典の参照、安全の点検の記録、設計の判断
外へ渡す型: 安全の点検の記録、問題台帳、方針外の課題の記録、検証の記録

### 遷移

| 元 | 先 | 条件 |
|---|---|---|
| `intake` | `entry-check` | — |
| `entry-check` | `triage-ask` | 問題がある行か、人の判断が要る行がある |
| `entry-check` | `final-ok` | どちらも無い |
| `triage-ask` | `entry-check` | 人が、この一巡の中で事実を確かめて点検し直すと決めた（範囲や許可を広げたときを含む） |
| `triage-ask` | `final-ok` | 全部の行に人の決定（直す、受け入れる、期限つきで保留）が付いた |

### 受付で決めること

- 点検する入口と応答（画面、データを返す窓口、ファイルの取得）、環境、対象の版。
- 要求を送ってよい相手の許可の記録: 自分たちが管理するホスト、環境（本番を含むか）、要求の種類（状態を変えない要求だけ）、数の上限と間隔、期間、点検用の利用者を使うか、許した人。記録が無ければ、工程 `entry-check`（点検する）は要求を作るところまでで止まる。
- 使っている部品の告知も見るか。
- 前回の点検の記録があるか（点検し直しなら、前回の記録を入力にする）。

## 振り分け

一言の依頼から、どの工程に入るかを決める。迷ったら、依頼者に一度だけ聞く。

| 依頼の言い方・状況 | 入る工程 |
|---|---|
| 「今の公開サイトの安全の設定を点検して」「管理画面のヘッダと Cookie を見て」 | `intake` → `entry-check` |
| 「走査の道具の指摘を仕分けて」 | `intake` → `entry-check`（道具の結果を原典の参照として受ける） |
| 「直したので点検し直して」 | `intake` → `entry-check`（前回の点検の記録を入力にし、当たった行を閉じる） |
| 「この指摘は受け入れていい？」 | `triage-ask` |

変更の差分が安全かを見る依頼（「この PR のセキュリティを見て」）は、この組み合わせではなく、差分のレビューで扱う。

## 工程の間の決まり

- 工程 `entry-check`（点検する）の前に、許可の記録を受付で確かめる。許可の外へ要求を送らない。第三者のホストには送らない。送るのは状態を変えない要求だけで、値を変えて送る走査や攻撃に当たる要求は、この組み合わせでは送らない。要ると分かったら、問題台帳に書いて工程 `triage-ask`（人が決める）で人に返す。
- 本番は、許可の記録が本番を含み、普通の利用者と同じ読むだけの要求のときだけ見る。
- `triage-ask` で人が決めるのは、行ごとに、直す・受け入れる・事実を確かめる、のどれか。問題台帳の人の決定の欄に書く（判断の区分の欄は変えない）。受け入れは、承認した人、範囲、見直す期限を付けて方針外の課題の記録に書き、その記録から問題台帳の識別子を指す。担当が受け入れを決めない。
- 事実を確かめるとき、この一巡の中で確かめられるなら `entry-check` に戻って点検し直す。待つ必要があるなら、期限つきの保留として工程 `final-ok`（最終確認）で終え、事実が届いたら新しい一巡で点検し直す。
- 直すと決めた行は、この組み合わせでは直さない。問題台帳を原典の参照として渡し、別の組み合わせとして起こす（受ける側が受付で不具合の報告にする）。
- 直した後の点検し直しは、前回の点検の記録を入力にして受付（`intake`）から始め、当たった行を閉じる。点検しなかった項目を、閉じたとしない。
- 点検の記録と問題台帳は、未修正の弱点と内部の構成の一覧になる。置き場所、共有の範囲、外へ渡す前の確かめは、型の一覧の「本番の事実と、記録の扱い」に従う。

どの工程にも当てはまる決まり（中断と再開、途中の問い）:

- 中断するとき、作業の一部を別の担当に頼むとき、再開するときは `dev-work-continuity` を使う。
- 再開したら、控えと今の状態を照らす。人が決めた状態にある成果物の部分（許可の記録、`triage-ask` の判断の区分と受け入れ）が変わっていれば、誰が変えたかを問わず人に確かめる。許可が期限を過ぎていたら、送る前に人に確かめる。
- 作業の途中で進めなくなって人に問うときは、1回に1問にし、選択肢の前に、起きていること、影響、得失、推奨を短く書く。問題台帳など、型に載せてまとめて出す問いは、この数に入れない。

## 終わり方

- `final-ok` で、人が点検の記録と問題台帳と方針外の課題の記録を確かめたら終える。
- 直すと決めた行が残っていれば、その行と問題台帳の所在を、次に起こす組み合わせの原典の参照として渡す。
- 外へ渡す型（点検の記録、問題台帳、方針外の課題の記録、検証の記録）の置き場所は、案件の決まりに従う。
