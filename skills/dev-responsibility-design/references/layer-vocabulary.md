# 用語の対応（層の名前を使う案件向け）

本文の4つの責務を、層の名前で呼ぶ案件での対応。案件の呼び方があれば、そちらを優先する。

| 本文の責務 | DDD の層での呼び方の例 | 置くものの例 |
|---|---|---|
| 業務の判断 | ドメイン層 | エンティティ、値オブジェクト、集約、ドメインサービス（純粋な計算） |
| 手順の調整 | アプリケーション層 | ユースケース、アプリケーションサービス |
| 入出力 | プレゼンテーション層 | コントローラ、入力の検証、応答の整形 |
| 具体の仕組み | インフラストラクチャ層 | リポジトリの実装、外部のクライアント |

- 「整合性の単位」は、DDD では集約に当たる。
- 業務の判断が具体の仕組みに依存しないようにするには、業務の側にインターフェースを置き、具体の仕組みの側で実装する（依存の逆転）。
- フレームワークが層をまたぐ便利な機能（モデルから直接保存するなど）を持つときは、使ってよい範囲を設計の判断に書く。

## テストの境界との対応の例

| 責務 | 主に確かめる層 |
|---|---|
| 業務の判断 | 単体（依存なしで速く） |
| 手順の調整 | 結合（具体の仕組みを本物か、本物に近い代わりで） |
| 入出力 | 外側の境界（操作を呼んで、状態と応答を確かめる） |
| 具体の仕組み | 本物を通す結合（制約やトランザクションが本当に効くか） |
