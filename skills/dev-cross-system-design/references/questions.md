# 問いの一覧

システムをまたぐ機能、外部サービスを呼ぶ機能で、答えておく問い。各行に、答えか「当たらない: 理由」か「人の決定待ち（選択肢と既定）」を書く。案件に既定の決定の記録があれば、先に読み、そこで決まっている行は所在だけ書く。

| # | 区分 | 問い |
|---|---|---|
| 1 | 正本 | この機能で扱う関心事ごとに、どのシステムが正本を持つか |
| 2 | 正本 | 相手の識別子を自分の側に持つか。持つなら、相手で消えたときにどうするか |
| 3 | 用語 | 同じ語が二つのシステムで別の意味を持っていないか。持つなら、名前と列をどう分けるか |
| 4 | 契約 | 呼び出す操作（パス、メッセージ）は、どちらのシステムに置くか。版をどう扱うか |
| 5 | 契約 | 相手の失敗の種類を、自分の側のどのエラーの種類に写すか（文言はエラーの設計で決める） |
| 6 | 同期 | 利用者はその場で結果を必要とするか。同期か非同期か |
| 7 | 失敗 | 途中で失敗したとき、まとめ役はどのシステムか。補償できるか |
| 8 | 失敗 | 取り消せない資源（お金、在庫、外部で発行した識別子）はどれか |
| 9 | 失敗 | 補償のとき、認可を緩める必要があるか（緩めない方を既定にする） |
| 10 | 起動 | 利用者を別のシステムへ渡すとき（リダイレクト、リンク）、認可を誰がどこで検証するか |
| 11 | 起動 | URL や送る内容に、個人情報や秘密の値が載っていないか |
| 12 | 観測 | 一つの操作を、システムをまたいで追える識別子があるか |
| 13 | 時計 | 期限や順序を、どのシステムの時刻で決めるか |
| 14 | 進化 | 相手の契約が変わったとき、どちらが先に変わるか。並行して動く期間はあるか |
| 15 | 既存 | 既存の導線を流用するか、廃止するか、並べて動かすか |
| 16 | 受信 | 相手から届く通知（Webhook など）の送り主をどう検証し、重複・順不同・届かない場合をどう扱うか |

## 既定の決定の記録の雛形

案件として何度も同じ問いに答えるなら、次の形で既定の決定を残し、以降は所在を書くだけにする。

- 背景: どんな機能で、なぜ決める必要があったか。
- 決定: 人が採った行だけ。採っていない案は書かない。
- 対象外: この決定が当てはまらない場面。
- 見直す契機: どんな変化があったら決め直すか。
