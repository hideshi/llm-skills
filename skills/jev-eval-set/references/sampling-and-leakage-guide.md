# サンプリング & リーク防止ガイド（数値非固定）

本ガイドは手順のチェックリストである。最低件数・目標比率・信頼区間などの**数値はプロジェクト入力**とし、ここにハードコードしない。

---

## 1. サンプリングの観点

- **スキーマ整合**: ラベル空間は architect の criteria / レベルと一致させる。
- **層化**: クラス稀少・チャネル・言語・時期など、業務上偏りやすい軸を入力で指定し、層ごとに拾う。
- **境界ケース**: 選択肢の境界、複合用件、脱出選択肢（`none` / `other`）を意図的に含める。
- **時間**: 可能なら評価分割を学習・プロンプト調整に使った期間と分離する（方針は入力）。
- **敵対的・誘導的入力**: セキュリティレビューと連携し、必要な場合のみ評価セット方針に含める。

---

## 2. リーク防止

- 同一 ID・同一本文・近傍重複が train/dev と eval をまたがないこと。
- 会話・チケット・顧客など**同一主体**が分割をまたいでヒントにならないこと。
- ラベルや正解根拠が state／プロンプトに混入していないこと。
- レポートやログに eval 本文を貼ってプロンプト改善へフィードバックしない運用にする（改善は draft 側データで行う）。

---

## 3. freeze 前の確認

- ラベル承認と freeze 承認が分かれているか（兼務可だが記録は分ける）。
- `datasetVersion` の計算方法（内容ハッシュ、日付タグ＋連番等）が実験リポで再現可能か。
- 変更したら `superseded` とし、較正側の `validationStatus` を `PENDING` に戻す必要があることを関係者に伝えるか。
