# リバース発見ガイド（候補検出）

要件文書が薄い／無いときに、実装から仮説を刈るための参照。契約の中核は `SKILL.md`。本ファイルは探し方の例示のみ。

## 探し方の型（例）
- 分類・トリアージ・ルーティング分岐
- 緊急度／優先度／深刻度などの段階評価
- Yes/No・フラグ（spam、違反、エスカレーション要否）
- 人手レビュー／手動承認への分岐
- 既存の LLM 呼び出しのうち、**生成ではなく有限ラベル**を返しているもの

後回し: 単純な CRUD、キーワード `includes` のみ、数値・日付の決定論比較。

## 軽い刈りで書いてよい／いけない
- **よい**: パス／関数または Requirement ID、責務の一文、一次資料区分（要件あり／なし）
- **いけない**: §1 ハードゲート・除外・★スコアの各項目への合否、プリミティブ確定、TCO、ADR 要否

§1 の判定基準を1項目でも適用した時点で「深掘り」とみなす。

## コード兆しとゲート目安（深掘り時）

| コード上の兆し | 目安 |
| :--- | :--- |
| `text.includes('spam')` のみ | 意味理解ゲートで落ちやすい |
| 部署を請求／技術／営業に振分 | choice 向き |
| 「要約を書け」 | 非生成ゲートで落ちる |
| 緊急度 Low/Med/High | score 向き |
| 在庫数カウント＋閾値 | 除外（計算本体） |
| 外部 API 後に初めて分かる事実 | 証拠充足で落ちる（先に state 化すれば別） |
