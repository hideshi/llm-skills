# Git

統合時の衝突の向き（ours / theirs）の確定、未解決の索引の読み取り、隠れ衝突と解消後の確かめを Git で行うときの資料。

- 確かめた版: Git 2.47.3、Linux
- 確かめた日: 2026-11-13
- 【実行】は小さなリポジトリを作って実際に動かして確かめたこと、【資料】は公式の資料で読んだだけのこと

## 衝突の段（stage）と操作ごとの向き

`git ls-files -u` は未解決のパスの索引を段（1〜3）で出す。以下の4操作すべての段の向きをテストリポジトリで確認した（【実行】）。

| 操作 | 段 1（基準 / base） | 段 2（ours / `HEAD`） | 段 3（theirs） | 注意 |
|---|---|---|---|---|
| `git merge` | 共通の祖先 | 今の枝（受け入れる側） | 取り込む枝（`MERGE_HEAD`） | 双方追加（`AA`）は段 1 が無い（【実行】） |
| `git rebase` | 再適用中のコミットの親（通常の非マージコミットのとき。根のコミットやマージコミットの再適用は別に確かめる） | **上流・付け替え先の系列** | **再適用中の自分のコミット** | `merge` と ours / theirs が**逆になる**（【実行】） |
| `git cherry-pick` | 摘み取るコミットの親 | 今の枝 | 摘み取るコミット | 1コミット分の差分だけを見る（【実行】） |
| `git revert` | 打ち消すコミット側 | 今の枝 | 打ち消す前の親側 | 逆の差分の意味として読む（【実行】） |

```sh
# 未解決のパスと状態記号（UU / AA / UD / DU など）
git status --porcelain
git ls-files -u

# 各段の内容を取り出して比べる（存在しない段は出力しない）
git show ":1:<パス>"
git show ":2:<パス>"
git show ":3:<パス>"
```

## 解消後の確認

```sh
# 衝突マーカーや空白の乱れが残っていないか（未登録側とステージ済みの両方を調べる。【実行】）
git diff --check
git diff --cached --check

# 未解決の索引が残っていないか（出力が空なら 0 件）
git ls-files -u

# 既に add した索引側のマーカー残存、および作業ツリー側の残存を調べる（diff3 形式の ||||||| も含める。【実行】）
# `=======` は Markdown・reST の罫線にも一致するため、当たった行は前後の <<<<<<< / >>>>>>> と組で見て判断する
git grep --cached -n -E '^(<{7}|\|{7}|={7}|>{7})( |$)' -- "<解消したパス>"
git grep -n -E '^(<{7}|\|{7}|={7}|>{7})( |$)' -- "<解消したパス>"

# 隠れ衝突の探索（片方で消えたファイルを列挙し、別ファイルに残る参照を全探索する。【実行】）
git diff --name-status --diff-filter=D "<基準>" "<自分側または相手側>"
git grep -n "<消したシンボルやパス>"
```

## 落とし穴

- **rebase 中の ours と theirs は merge と逆になる**（【実行】）。`feat` を `main` の上に付け替えて衝突したとき、`stage 2`（`ours`）は `main` 側、`stage 3`（`theirs`）は `feat` 側になる。
- **`AA`（双方追加）は段 1 が無く、`UD` / `DU`（片方が削除・片方が変更）は段 2 か段 3 の片方が無い**（【実行】）。`git show :1:<パス>` が失敗して止まらないよう、ある段だけを取り出す。`DD`（双方削除）・`AU` / `UA`（片方だけが追加。改名の衝突で出やすい）も同じく、ある段だけを見る（【資料】）。
- **`--theirs` / `--ours` の丸ごと上書きで隠れ衝突を残しやすい**。片方が削除して他方が残したパス（`UD` / `DU`）や、別ファイルへの参照切れは自動統合でも検出されないため、解消後に参照を全探索する。
