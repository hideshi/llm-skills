# パラメータ掃引プレイブック（較正の子手順）

本プレイブックは **較正（`jev-calibration`）の子ステップ**である。ゲート数値・閾値の具体値はプロジェクト入力／実験成果物とし、ここに焼かない。掃引の順番は **推奨** であり、固定契約（ハードコントラクト）にはしない。

---

## 1. 必須成果: 比較表

掃引を行った場合、少なくとも次の列を持つ **比較表** を詳細較正レポート（および定形結果レポート §4.3）に残す。

| 候補 ID | 変更した変数（1つ、または相互作用疑いのペア） | その他固定条件 | 主要指標（ゲート参照） | 失敗モード要約 | 採用可否 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| A0（初期仮説） | — | … | … | … | 基準 |
| A1 | [変数名] | … | … | … | |

- 数値は実験成果物から転記する。スキルに例示閾値をハードコードしない（説明用の仮値を書く場合は **例** と明記）。
- 「どれを採用したか／棄却したか」と採用ルールを一文で添える。

---

## 2. 1変数原則とペア掃引

- **既定**: 一度に動かす独立変数は **1つ**（1-variable）。他条件は固定し、効果の帰属を明確にする。
- **ペア許容**: 相互作用が疑われるときに限り、**2変数のペア**掃引を許可する。疑った相互作用と、なぜ1変数では不足かを比較表の備考に書く。
- 3変数以上の同時変更は、帰属が崩れるため推奨しない（やむを得ない場合は探索と確定を分け、確定は1変数またはペアに戻す）。

---

## 3. 閾値のみ変更時のオフライン再スコア

- **問い文・criteria・ラベル・state スキーマが不変**で、閾値／帯域分岐ルールだけを変える場合は、同一のモデル出力ログに対する **オフライン再スコア** で足りる（再推論は必須ではない）。
- 再スコア範囲（全件／層別／失敗ケースのみ）と件数感を比較表または §4.3 に残す。

---

## 4. 推奨順序（推奨であり固定契約ではない）

次は経験上の **推奨** 順である。案件の失敗モードに応じて飛ばしてよい。順序自体をゲート条件にしない。

1. グローバル閾値（Dual Threshold の high/low 等）
2. 帯域別ルール（自動確定／REVIEW／Safe Default）
3. タイプ別・層別の分岐（例: 特定ラベルだけ人手強制）
4. （必要なら）問い文・criteria の設計変更 → この場合は §5 の二重再掃引トリガを検討

---

## 5. 二重再掃引トリガ（必須）

次の **意味** が変わったときは、閾値の継ぎ足しではなく **較正側の再掃引（必要なら評価セット側の再 freeze）** を必須とする。文言の言い換えのみ（意味不変）は対象外。

| 変化の種類 | 例 | 対応 |
| :--- | :--- | :--- |
| ラベル空間の意味変更 | 選択肢の追加・統合・分割、脱出ラベルの業務意味の変更 | `jev-eval-set` で再 freeze（`datasetVersion` 更新）→ `validationStatus: PENDING` → 較正で再掃引 |
| criteria / 問いの判定境界の意味変更 | 何をもって違反とするかの定義変更 | 同上（設計は `jev-logic-architect`、データは eval-set） |
| Score アンカーの意味変更 | レベルに紐づく行動定義（例: medium の業務アクション）の変更 | 同上 |

**対象外**: 誤字修正、同義の言い換え、例示文の追加で境界の意味が変わらないとき。意味が変わったかどうか判断が難しい場合は HITL で確認し、迷ったら再掃引側に倒す。

---

## 6. 版安定ゲート（datasetVersion 変更後）

- `datasetVersion` が変わったら、共有語彙に従い `validationStatus` を **`PENDING`** に戻す（新語彙を増やさない。`UNVALIDATED` 等は用いない）。
- **再測定** = `jev-calibration`（同一ポリシーでゲート再計測）。**再 freeze** = `jev-eval-set`。
- 同一ポリシーを再測定しゲートを満たすまで `VALIDATED` へ昇格しない。

---

## 7. 用語メモ（P1）: `label_agreement` と `human_review_rate`

| 用語 | 意味 | 混同しやすい点 |
| :--- | :--- | :--- |
| `label_agreement` | 予測ラベル（または閾値適用後の最終ラベル）と **正解ラベル** の一致率 | 人手レビューに回した比率ではない |
| `human_review_rate` | 経路として **人手 REVIEW** に流した比率（閾値帯・ルール由来） | 正解との一致率ではない |

ゲートに使う指標がどちらなのかを、較正レポートの指標表で明示する。
