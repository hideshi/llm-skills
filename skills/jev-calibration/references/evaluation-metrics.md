# 評価指標の定義（合格ライン数値は入力）

本ドキュメントは指標の**定義**のみを示す。目標値・信頼区間・最低サンプル数はプロジェクトのゲート基準（入力契約）で与える。

---

## 1. 一致率・精度系

- **一致率（Accuracy）** / **`label_agreement`**: 全件のうち、予測ラベル（または閾値適用後の最終アクション）が正解と一致した割合。**人手 REVIEW に流した比率（`human_review_rate`）とは別指標**である。
- **Precision / Recall / F1**: クラスまたは「自動 BLOCK」等のアクション単位で定義する。どのクラスを正例とするかは入力で明示する。
- **マクロ / マイクロ平均**: 不均衡時はどちらをゲートに使うかを入力で指定する。

---

## 2. 混同行列

- 行を正解、列を予測（またはその逆）で固定し、レポート間で入れ替えない。
- choice: ラベルキー単位。score: レベル単位またはアクション単位（入力で定義）。noul: 閾値適用後の ALLOW / BLOCK / REVIEW などアクション単位を推奨。

---

## 3. 帯域分布

- 閾値（または confidence 帯）で区切った件数比率。
- 典型: 自動確定帯 / 中間（REVIEW）帯 / Safe Default 帯。
- 帯の境界値そのものは較正の出力（推奨閾値）であり、スキルに固定しない。

---

## 4. フォールバック率・人手レビュー率

- 全件のうち、LLM エスカレーション・人手 REVIEW・Safe Default など**非自動確定**に流れた割合。
- 内訳（REVIEW / LLM / Safe Default）を分けて報告できると TCO 試算と接続しやすい。
- **`human_review_rate`**: 経路として人手 REVIEW に流した比率（閾値帯・分岐ルール由来）。`label_agreement`（正解一致）と混同しないこと。ゲートに使う側をレポートで明示する。

---

## 5. （任意）確率較正

- **Reliability / ECE**: 予測確率ビンごとの実正解率とのずれ。
- 較正が崩れている場合、閾値だけではゲートを満たせないことがあり、そのときは `REJECTED`（スキーマ・問い再設計）または前処理変更を検討する。

---

## 6. 人手最終フィードバック → トリアージ（観測連携）

観測側（`jev-observability` の人手最終判定イベント）から戻るときの**短い振り分け**。合格ライン数値は入力。承認業務フローは扱わない。

| 主な信号 | 振り分け | 行き先 |
| :--- | :--- | :--- |
| 不一致＋理由が情報不足・分布外・境界曖昧 | データ不足 | `NEEDS_MORE_DATA` → `jev-eval-set`（境界ケース追加） |
| 不一致＋理由が転用評価・必須重視・Jev見落とし／過剰警戒など意味ずれ | 問い／criteria 改訂 | `REJECTED` 相当 → `jev-logic-architect`（改訂後 `PENDING`） |
| スキーマは妥当で帯・Dual の切り方ずれ | 閾値調整 | 本スキルの Dual／ゲート掃引（プレイブック） |

**一行指針**: 不一致＋理由コード → eval 境界追加（データ）／criteria・問い改訂（prompt）／Dual・ゲート調整（閾値）。
