# パラメトリックに 3D モデルを作る

CAD の道具のスクリプトを設計の正本にして、部品の形状を作り、組み立てて検査し、人が確かめられる形で書き出す。道具ごとの書き方は道具の資料に分け、本文には道具によらない決まりだけを書く。

## 入力

| もの | 必須 | 使い方 |
|---|---|---|
| 何を作るか | 必須 | 部品の役目、相手の部品、使われ方 |
| 一次情報の記録 | 条件付き（規格・ルール・市販品の寸法・素材の値に縛られるとき必須） | 項目の識別子（`SRC-xx`）と状態。パラメータの根拠にする |
| 方針 | 任意 | 人が決めた造形の向き、素材、サポートの有無、すきまの考え方など |
| 案件の制約 | 任意 | 造形できる大きさ、単位と座標系、置き場所の決まり（案件の指示の文書にあれば従う） |
| 使う道具 | 必須 | 道具の名前と、手元で入っている版。決まっていなければ、作る前に依頼者に確かめる |
| 実測の値 | 任意 | 試作や相手の部品を測った値。一次情報とは分けて受ける |

- 縛られる値に根拠が無いときは、作り始めない。根拠を先に記録するよう返す。仮置きで進めるかは依頼者が決める。
- 安全に関わる値（防護、強度、硬さ、肉厚の下限など）が未確認のままなら、形状は作っても「確定ではない」と結果に書く。

## 出力

- 設計のスクリプト（正本）。案件の置き場所に置く。
- 生成物: 道具の元の形式（例: `.FCStd`）、交換用の STEP、造形用の STL（または 3MF）。生成物は置き場所を分ける（例: `out/`）。
- 検査の記録: 組み立ての出力（外形、体積、検査の結果）。
- プレビュー: 断面か、外形の画像。
- 確認の手順: 案件の README などに、主な寸法、根拠の所在、組み立て直す命令、道具で開いて確かめる手順を書く。

## 使わない場面

- 規格・ルール・データシート・市販品の寸法を確かめる（一次情報の記録を作る、別の仕事）。
- 造形の向き、素材、サポートの有無などの方針を決める（決めるのは人。この単位は案と影響を返すだけ）。
- スライサーの設定、印刷そのもの、試作の実測。
- 外観のレンダリングや意匠のスケッチ。

## 決まり（道具によらない）

1. **スクリプトが正本**: 形状は、道具のスクリプト（または道具のコードの形式）だけで作る。道具の保存ファイルの中身（XML、バイナリ）を直接書き換えない。GUI で手直しした形状を正本にしない。手直しが要るなら、スクリプトに戻して直す。
2. **パラメータは一か所**: 主要な寸法、すきま、公差、検査の値を、スクリプトの頭の一か所に集める。値ごとに根拠を書く（`SRC-xx（確認済み）`、`SRC-xx（未確認・仮置き）`、`実測（日付・道具）`、`設計の判断`）。根拠の無い数値を形状の関数の中に直に書かない。
3. **作る前に確かめる**: 値の組み合わせ（最小の肉厚、すきまの符号、穴が外形を突き抜けないか、造形できる大きさ）を、形状を作る前の関数で確かめ、成り立たなければ止める。
4. **作った後に確かめる**: 次をすべて確かめ、どれかに落ちたら書き出さずに 0 でない値で終える。
   - 形状: 正しい B-Rep、ソリッドが1個、閉じている。
   - メッシュ: 閉じている、非多様体が無い、自己交差が無い。
   - 外形: 造形できる大きさに収まる、底面が決めた高さ（例: Z = 0）にある。
   - 案件の値: 決めた最小の肉厚などを、作った形状で測れるものは測る。
5. **見て確かめられる形にする**: 断面か外形のプレビューを書き出す。道具の元の形式で開いたときに、部品が表示され、全体が見える視点で開くようにする（道具によっては、手順を足さないと表示が切れて保存される。道具の資料を見る）。
6. **単位と座標系を書く**: 単位、上の向き、原点、造形の底面を、スクリプトの頭に書く。
7. **流し方を一つにする**: 組み立て直す命令は一つにし、README に書く。

## 手順

### 1. 道具を決めて資料を読む

依頼者か案件の指定で道具を決め、手元の版を命令で確かめる（`--version` など）。[道具の資料の一覧](references/tools/README.md)にその道具の資料があれば読む。無ければ、一覧の「資料の無い道具を使うとき」に従い、公式の資料で確かめた点だけを使う。存在を確かめていない関数やオプションを書かない。

### 2. 値と根拠を並べる

一次情報の記録、方針、案件の制約、実測の値から、パラメータの表を作る。縛る値ごとに根拠の識別子と状態を書く。未確認の値は仮置きと分かるようにする。

### 3. スクリプトを書く

道具の雛形があれば写して使う（FreeCAD は [雛形](templates/freecad_build.py)）。パラメータ、作る前の検査、形状、作った後の検査、書き出し、プレビューの順に分ける。

### 4. 組み立てて検査する

命令で流し、終わりの値と出力を確かめる。検査に落ちたら、値か形状を直して流し直す。落ちた検査を外したり、閾値を緩めたりして通さない。緩める必要があるなら、理由を付けて依頼者に返す。

### 5. 開いて見る

プレビューを自分で開いて、狙った形か（穴の位置、肉厚、底面）を確かめる。道具で開いたときの表示と視点も、道具の資料の手順で確かめる。

### 6. 書き残す

確認の手順に、主な寸法、根拠の所在（一次情報の記録の場所）、未確認の値の一覧、組み立て直す命令、道具で開いて見る手順を書く。結果には、検査の出力と、確定でない値を添える。

## 終了条件

- スクリプトだけで、生成物が作り直せる。
- 作った後の検査がすべて通り、その出力が残っている。
- パラメータの値すべてに根拠の種類が書かれ、未確認の値が一覧になっている。
- プレビューを自分で見て、狙った形だと確かめた。
- 確認の手順が案件の置き場所にある。
