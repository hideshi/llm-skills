# 試験の概念へのつなぎ方

振り返りの気づきを、IPA の情報処理技術者試験と情報処理安全確保支援士試験で扱う概念へつなぐときに読む。目的は、今回の経験を一般的な名前のある概念として持ち帰ることで、試験対策や出題範囲の網羅ではない。

## 公式情報を先に確かめる

試験の区分・名称・出題範囲・シラバスの版は、紹介する時点で IPA の公式資料を確かめる。

- 試験要綱・シラバス: https://www.ipa.go.jp/shiken/syllabus/gaiyou.html
- 試験情報（制度の見直しや新着）: https://www.ipa.go.jp/shiken/

現行版と、改訂の案・新制度の案を区別する。確かめられないときは「最新版に沿っている」「この試験に出る」と断定せず、分野の名前として紹介する。このファイルにはシラバスの版を書かない（版は頻繁に変わるため）。

### 制度の移行（2026 年 11 月に確認した状況）

- 現行の区分は、2026 年度の試験の実施をもって終わる予定とされている
- 2027 年度から、応用情報技術者試験と高度試験を大くくりにして、マネジメント、データ・AI、システムの三つの領域の「プロフェッショナルデジタルスキル試験（仮称）」へ再編し、「データマネジメント試験（仮称）」を新設する案が示されている。いずれも検討中で、変わる場合がある
- 基本情報技術者試験と情報セキュリティマネジメント試験は継続、情報処理安全確保支援士試験は一部変更の予定とされている
- 現行の各区分と新しい区分の個別の対応は、確認できていない

このため、概念は区分名ではなく **分野の名前** を主にして紹介し、区分名は「どの段階・分野の知識か」の目印として添える。新制度の名前を出すときは「仮称」「案」を付ける。

## 段階と区分の目安

| 段階 | 区分（現行） | 扱う知識の目安 |
|---|---|---|
| 入口 | 基本情報技術者試験 | IT の仕組み、開発、セキュリティ、マネジメントの基礎 |
| 応用 | 応用情報技術者試験 | 基礎を使って、設計・管理・運用で判断する |
| 高度 | ITストラテジスト、システムアーキテクト、プロジェクトマネージャ、ネットワークスペシャリスト、データベーススペシャリスト、エンベデッドシステムスペシャリスト、ITサービスマネージャ、システム監査技術者 | 特定の分野で、方針・方式を決め、責任を持って判断する |
| 高度（別の制度） | 情報処理安全確保支援士試験 | セキュリティの設計・対策・事案への対応。IPA は高度試験と並べて別に扱っている |

## 段階の選び方

1. **既定は基本情報の範囲。** 利用者の理解が分からないときは、基本情報で扱う概念から入る
2. **経験が基本情報の範囲で説明しきれないときは広げる。** 方式のトレードオフ、計画と管理、運用の仕組み、監査、攻撃者の視点など、判断の質が問われる摩擦なら、応用情報や該当する高度試験の分野の概念を選ぶ
3. **利用者の理解に合わせる。** 会話で基本の概念を使いこなしている、または高度試験の学習中だと本人が言った場合は、高度の分野の概念を優先してよい。学習中の区分が分かっていても、今回の経験と関係が薄い概念は紹介しない
4. **一段ずつ。** 高度の概念が基本の概念を前提にするなら、前提を一言添える。ただし用語は合わせて三件まで（SKILL.md §2）
5. **段階で人を評価しない。** 「高度の概念を紹介した」ことを、利用者の水準の判定や記録にしない

## 経験と概念の例

例は、つなぎ方の型を示すもの。今回の経験と機構が合うかを確かめてから使い、合わなければ使わない。

### 基本情報の範囲

| 経験 | 概念 |
|---|---|
| 動作の速さや障害時の条件を決め忘れた | 要件定義の機能要件・非機能要件 |
| 情報漏えいだけを考え、改ざんや停止を見落とした | 情報セキュリティの機密性・完全性・可用性 |
| 内部の状態を自由に書き換えて不整合が起きた | オブジェクト指向のカプセル化 |

### 応用・高度の分野

| 経験 | 概念 | 分野の目印（現行の区分） |
|---|---|---|
| 機能の優先度を開発の手間だけで決め、事業上の効果を比べなかった | 投資対効果、IT 戦略と事業戦略の整合 | ITストラテジスト |
| キャッシュで速くしたら、古いデータが見えるようになった | 性能と一貫性のトレードオフ、方式設計 | システムアーキテクト |
| 途中で機能が増え続け、終わりが見えなくなった | スコープ管理、スコープクリープ | プロジェクトマネージャ |
| 手元では動くのに本番だけつながらず、原因が名前解決の古い結果だった | 名前解決とキャッシュの有効期間（TTL） | ネットワークスペシャリスト |
| 同時に更新したら件数がずれた | 排他制御、トランザクションの分離レベル、ロストアップデート | データベーススペシャリスト |
| 処理が重なると制御が間に合わなくなった | リアルタイム性、割込み、資源の制約 | エンベデッドシステムスペシャリスト |
| 同じ障害を毎回その場しのぎで直している | インシデント管理と問題管理の違い | ITサービスマネージャ |
| 誰がいつ設定を変えたのか追えなかった | 監査証跡、職務の分離 | システム監査技術者 |
| ログインしていれば他人のデータも取得できた | 認証と認可の区別、アクセス制御の不備 | 情報処理安全確保支援士 |

複数の要素からなる概念（例: 機密性・完全性・可用性）は、違いの整理が今回の理解に役立つ範囲だけ説明する。分野が重なる概念（例: 性能と一貫性は設計とデータベースの両方）は、今回の摩擦に近い側の分野で一つだけ示す。

## 紹介の書き方

SKILL.md §2 の表の一行として書く。意味は今回の経験に必要な粒度にし、なぜ今回の経験と関係するかを一言添える。試験の分野名は、確かめた場合だけ「（基本情報の〜分野）」「（高度試験の〜の分野）」のように添える。利用者が用語を知っているとは仮定しない。
