## 先行の手法

| 手順の箇所 | 手法 | 出典 | 確かめた水準 | 同じところ | 変えた・足したところ |
|---|---|---|---|---|---|
| 1. 作る前に元の場所を確かめ、台帳を整える、2. 作業場所を作り、除外された設定と依存を揃える | 複数作業ツリーの管理（linked worktree、同じ枝の重複チェックアウト防止、強制削除の抑止） | Git 公式マニュアル [git-worktree](https://git-scm.com/docs/git-worktree)（DESCRIPTION、`-f --force`、`remove`）。2026-11-13 本文確認 | 原典を読んだ | 一つのリポジトリに複数の作業ツリーをぶら下げ、同じ枝の重複使用を止め、未保存の変更がある作業ツリーの削除を既定で止める | 作業ツリーの追加・削除だけでなく、版管理が分けない依存の実体、設定、DB・実行枠の隔離と確認までを手順に含めた |
| 2. 作業場所を作り、除外された設定と依存を揃える、4. 統合を確かめてから片付ける | 共有スタッシュを使わない退避（複数作業ツリー間でスタッシュ領域が共通になるための回避） | Git 公式マニュアル [git-stash](https://git-scm.com/docs/git-stash)（DESCRIPTION）。2026-11-13 本文確認 | 原典を読んだ | `stash` はリポジトリ共通の履歴としてローカル変更を退避・復元する仕組みである | 並行する作業場所どうしで変更が混ざったり別作業で取り出されたりするのを防ぐため、`stash` による避難を禁止し作業場所固有の枝での退避に統一した |

## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 環境変数を渡しただけで隔離したとみなさず、処理の接続先と読み込み元のコードを実測で確かめてから動かす | Git が分けるのはコードだけで、DB・キュー・共有の常駐処理・リンク先の依存は元の作業場所側を向きうるため | 検証の記録と片付け時の確認で、別作業場所や共有資源を参照したまま実行された事故件数を数え、確認項目を見直す |
| 作業場所の台帳の正本を元の作業場所側に置き、分けた作業場所側の写しを編集しない | 複数の作業場所から同じ台帳を書き換えると衝突や更新漏れが起きるため | 台帳で管理した並行作業のうち、台帳と実際の `worktree` 一覧や資源状態が食い違った件数を台帳と作業状態の控えで追い、運用を見直す |
| 消す前に未確定の変更・未反映の履歴・版管理から除外された成果物の退避を確かめ、専用資源だけ所有を確認して解放する | 除外された成果物（録画や生成物）が作業場所の削除で失われたり、共有資源を誤って消したりするのを防ぐため | 片付け時の作業状態の控えと検証の記録で、退避漏れによる成果物喪失または所有確認なしの資源削除の件数を記録し、確認手順を見直す |
