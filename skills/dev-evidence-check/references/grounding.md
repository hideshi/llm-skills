## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 確かめる順を「製品の正規経路で到達 → 録画なしで通す → 必要画面を全部取る → 提出する形に組み立てる → 提出する者が最初から最後まで自分で見る → 確定・宣言・引き渡し」に固定し、下流を上流より先にしない | テスト通過やコマンド終了を証拠の確認済みと取り違え、映っていない・壊れた成果物を提出する事故を防ぐため | 自己視聴と段階順を通しても受入の証拠・レビュー結果で不備や撮り直しが出た割合と差し戻し件数を数え、各段階の停止条件を見直す |
| 組み立てた成果物で証拠を取り、注釈が言う場面の実写・非空表示（伏せ字のみの表を不可とする）・試験用仕掛けでの代用禁止を完了条件にする | 開発用表示や古いビルド、空画面や伏せ字だけの画面では製品が実際に動く証拠にならないため | 実写・非空条件を満たした提出物でも確認者の差し戻し・追撮りが起きた割合をレビュー結果・受入の証拠で数え、完了条件の粒度を見直す |
| 確定の対象を動画や画像単体ではなく「記録と実物のまとまり全体」とし、所在とハッシュの一致・作り直し時の確定解除・独立した操作としての確定を求める | ファイルの差し替えや古い版の取り違え、途中失敗版の誤確定を防ぐため | 差し替えや再生成で実物と記録が食い違い誤確定した件数を記録し、ハッシュ検証と確定解除の運用を見直す |
| 録画の見やすさ（操作位置表示・追える速さ・中央への移動・読める状態から目安5秒停止・待機と表示停止の分離・業務語での字幕）を録画側で作り、道具別の落とし穴を道具の資料や公式資料で確かめ、製品コードを変えない | 撮影の都合で製品の画面や待機時間を歪めたり、ツール固有のフォント欠けや縮小・連結崩れで証拠が壊れたりするのを防ぐため | フォント欠け・停止時間不足・製品コード混入で証拠を取り直した件数を記録し、録画条件と5秒目安を見直す |
| 証拠の作りの問題と製品の不具合を混ぜず、親切な説明を足す改善案では情報漏えい（利用者の有無・トークン状態・内部情報）を点検する | 撮影不備を製品バグと誤認したり、説明文の追加でセキュリティ上の露出を増やしたりするのを防ぐため | 撮影不備の製品バグ誤認件数と文言改善による露出指摘件数を記録し、切り分けと点検の条件を見直す |
