## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 誰に、いつ、何を知らせるか、送らない条件、止められるかの正本は要件と業務規則に置き、文面の側は写して出どころを書く。欠けは上流へ返す | 文面の側で決めると、業務の約束が二か所に書かれ、片方だけが直されて食い違うため | 文面の設計の後に、文面の側だけで決めて後から要件に書き戻した件数を数え、返し方を見直す |
| 文面を独立の型にせず、設計の判断の観点の一つにし、人は設計の承認で採る | 文面はエラー、認可、送る仕組みの判断に依り、それらと同じ時に決まる。独立の工程にすると、戻り道と採用の無効の決まりが二重になるため | 文面の判断が設計の承認の後に変わった件数と、そのときに画面や試験の確かめ直しが漏れた件数を数え、置き場を見直す |
| 帳票の計算と端数処理は業務規則を指し、帳票の側は表示の書式だけを決める | 帳票で計算を決め直すと、画面や外部の契約の値と食い違うため | 帳票の値と画面の値が食い違った件数を数え、指し方を見直す |
| 法定の記載事項は、一次情報の項目と、適用を決めた要件か業務規則の両方を指し、どちらかが無ければ決定待ちにする | 原典があっても、その帳票に当たるかは別の判断で、解釈を文面の側に持ち込まないため | 決定待ちのまま実装に流れた件数と、後から記載の欠けが見つかった件数を数え、関門を見直す |
| 文面の種類と区分の語を閉じる（メール／アプリ内の通知／プッシュの通知／SMS／帳票、取引に要る知らせ／案内・宣伝） | 区分で止める手段と送る時間帯の扱いが変わり、語が自由だと試験で確かめる観点が決まらないため | どの語にも当たらず例外を書いた件数を数え、語の数を見直す |
