# 引継ぎの記録の例

型: 引継ぎの記録
形の一例。正本は型の一覧の欄。形式・節名・置き場所は任意で、案件に既に形があればその形に従う。値はすべて作り物。

題材は、確定した請求書の明細を直せないようにする変更。レビューの指摘の直しが終わった所で、セッションを区切るときに書いた記録。この例の識別子は、同じ題材のほかの単位の例と同じものを使う。

| 欄 | 中身 |
|---|---|
| 記録の宛先 | 次のセッション |
| 書いた時点 | 2026-11-12 18:00（作り物の日時） |
| 作業の場所 | リポジトリ `example-repo`、枝 `example-invoice-finalized`、作業ツリー `.worktrees/example-invoice`。消えうる一時の環境: なし |
| 記録の状態 | 有効 |
| 基準の作業状態の控えの所在 | `handoff/example-snapshot.md`（版 `c3d4e5f` と、監視するパスのハッシュ） |
| 未確定の変更とコミットしない理由 | `InvoiceLineService.ts`（`R-1` の直し）、`InvoiceLines.vue`（`R-2` の直し）、`InvoiceLines.test.ts`（`R-3` の直しで足した試験）が未確定。案件の決まりで、レビューの指摘の直しは人に見せてからコミットするため |
| 進めていた位置 | 組み合わせは既存のシステムを改修する流れで、レビューの一巡を回す工程（組み合わせと工程は、例の決まりで名指ししないので文で書いた。実際は、組み合わせの工程の識別子で書く）。そこまでの判定と道: 道は通常の道。初回のレビューの判定は変更要求（`reviews/example-review-1.md`）で、直して出し直した回数はまだ0回。レビューの指摘 `R-1`〜`R-3` の直しが終わり、人に見せる前。最後に流した検証: `python3 -I scripts/run_invoice_tests.example`（2026-11-12 17:40、通る） |
| この担当の役割 | 作った側 |
| 作業の状態 | 作業の一覧の `TASK-1`・`TASK-2` は終わり、`TASK-3` は決定待ち（確認事項 `Q-4` の回答待ち）。進行中の作業は無い |
| 人の決定と決定待ち | 決定: 確認事項 `Q-3`（確定した請求書の明細は変えられない。`docs/example-questions.md`）。決定待ち: `Q-4`（取り消せる人） |
| 自分で下した判断 | 画面の文の日付の書式は、共通仕様の書式にそろえる（担当の案。人の決定には回していない） |
| 委任中の作業 | なし |
| 届いていない連絡 | なし |
| 今止めているものと回避 | `Q-4` の回答待ち（`TASK-3`）。`TASK-3` 以外の作業は止めない |
| 次の一手 | 1. `R-1`〜`R-3` の直しを人に見せてコミットする。2. 直した所に絞ったレビューの依頼を出す。3. 承認されたら、検証の記録を取り直す |
| 次に読む原典と読む理由 | レビュー結果 `reviews/example-review-1.md`（直しの範囲を確かめるため）。設計の判断 `DD-7`（直列にする判断に触れていないことを確かめるため） |

資格情報と個人のデータは、値を写さず所在で示す欄。この例の案件では、記録に書くものが無かった。

再開の記録の欄（選んだ記録、照らした控えとの差と分け方、人に確かめたこと）は、再開したときに足す。この例は、書いた時点の記録なので、まだ無い。
