# サービスをまたぐ概念の地図

範囲が一つのシステムでなく、複数のサービスにまたがるとき、ドメインモデルを次の3点で書く。

1. 用語集: 用語、各サービスでの呼び方、定義。
2. 概念の関係: 概念どうしの関係と多重度（図にするなら、関係の図）。
3. 所有の表: どのサービスがどの概念の正本を持つか。

## 書く言葉

- 最初から、サービス群の正本として書く（一つのサービスの見方で書いて後から広げない）。
- 制約は、概念の関係として書く。
- 同じ名前で意味が違う概念は、サービス名で修飾して分ける。
- 日本語名は、利用者に見える表示名を正にする。
- 固定の規則と、既定の値（後から変えられるもの）を分ける。
- 概念が別のサービスへ引き継がれる関係は「〜しうる」で書く（必ず起きるとは限らない）。

## やらないこと

- 推論の仕組みや公理は扱わない。
- 実装の識別子、特定の機能への従属、画面、分類の軸を独立の概念にする、コードの列を写す、はしない。

## 作り方

- 第一の入力は、各サービスのドメインモデル。コードにしか無い知識は、先に各サービスのモデルへ返してから地図に載せる。
- 多重度、主体、条件は、各サービスのモデルで裏を取る。人の確かめは省かない。
- 1つの文書で、概念は50〜100を目安にする。超えるなら範囲を分ける。
- 地図と各サービスのモデルがずれていないかの判定は、人がする。
