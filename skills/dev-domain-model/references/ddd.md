# DDD で組むとき

案件が DDD（ドメイン駆動設計）で組むと決めたときの、言い換えと見分け方。本文の中立の語との対応を先に置く。ほかの単位の「DDD で組むとき」の資料も、同じ言い換えを使う。

| 本文の語 | DDD の語 |
|---|---|
| 一緒に変わるまとまり（一度に整合を守る単位） | 集約 |
| 管理するもの（識別子で区別するもの） | エンティティ |
| 値だけで区別するもの | 値オブジェクト |
| ドメインイベント | ドメインイベント |
| 範囲（用語の意味が一つに決まる範囲） | 境界づけられたコンテキスト |
| サービスをまたぐ概念の地図 | コンテキストマップ |
| 業務の判断（責務の配置の語） | ドメイン層 |

## 集約の境界の決め方

- 一緒に変わり、一度に整合を守らないといけない規則（不変条件）で囲む。
- 寿命、変わる理由、使われる段階が一致するかを見る。
- 迷ったら小さく分ける。またぐ規則は、ドメインイベントと後からの整合で守る。

## 候補の見分け方

| 候補 | 兆し |
|---|---|
| 値オブジェクト | 値が同じなら同じものとみなせる。変わるときは丸ごと入れ替える（金額と通貨、期間） |
| エンティティ | 属性が変わっても同じものとして追う必要がある |
| ファクトリ | 作るときに満たす規則が多く、作る手順に名前を付けたい |
| リポジトリ | 集約ごとに一つ。集約の外から中の部品を直接取り出さない |

## コンテキストどうしの関係

範囲が分かれるときは、用語の意味が変わる所で分け、関係（相手のモデルをそのまま使う、翻訳して隔離する、共通の部品を共有する）を、サービスをまたぐ概念の地図に書く。
