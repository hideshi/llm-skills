# 完了前に監査する

実装やレビューの担当が「終わった」と言った後、人に最終確認を求めてよいかだけを判定する。完了の主張は、自己申告として扱い、根拠に採用しない。読み取りが中心で、直す、確定する、承認を代行することはしない。

## 入力

| 型 | 必須 | 使い方 |
|---|---|---|
| 完了の主張 | 必須 | 監査の対象。根拠としては使わない |
| 完了条件の一覧 | 必須 | 監査の時点で、原典から全項目を読み直す。主張に書かれた範囲に限定しない |
| 検証の記録 | 必須 | 対象・範囲・日時・結果を、その後の変更と照合する |
| 追跡表 | 任意 | あれば結びつきを機械的に検査する。無ければ、その段を「該当なし」とする |
| 作業の一覧 | 任意 | あれば、作業ごとに終わりの条件と結んだテストケースの結果を確かめる |
| テストケース表 | 任意 | 受入条件と試験の結びつきを、ケースの側から確かめる |
| レビュー結果 | 任意 | 先に行われたレビュー。未解決の指摘を拾う |
| 方針外の課題の記録 | 任意 | 残作業の分類に使う |
| 設計の判断 | 任意 | 人の決定待ちや、人が採っていない担当の案が残っていないか。人が採った判断が、続けて使う文書に反映されたか、反映を後に回す記録があるか |
| 規模の判定 | 任意 | 終わる時に実際の差分で判定したもの。続けて使う文書への影響、運用の作業（本番の手順、依存）が当たるか、完了条件の承認し直しの要否を確かめる |
| 受入の証拠 | 任意 | 画面・録画・帳票が受入の本体のとき。確定の状態と自己視聴の結果を確かめる |
| 業務規則の一覧 | 任意 | 道に応じた検査のうち、業務規則に関わる項目（規則ごとのケース、指す規則の確かさ）を突き合わせる。無ければ、その項目を「該当なし」とする |
| ドメインモデル | 任意 | 道に応じた検査のうち、モデルに関わる項目を突き合わせる |
| 画面の設計 | 任意 | 道に応じた検査のうち、画面に関わる項目（画面と受入条件の結びつき、指す先の実在）を突き合わせる。人が採った版か、採り直し待ちが残っていないかも確かめる |

型の中身は [型の一覧](../dev-shared/references/artifact-types.md) を見る。

- 完了条件の一覧か完了の主張が手に入らないときは、判定を「止める」にして、何が無いかを返す。
- 検証の記録が無いときは、記録に頼る項目をすべて「未確認」の段として扱い、監査の中で自分で確かめられたものだけを段1にする。

## 出力

| 型 | 中身の補足 |
|---|---|
| 作業状態の控え | 監査の開始時と終了時の二つ |
| 完了判定 | 下の「判定の形」に従う |

## 使わない場面

- 差分の良し悪しをレビューする（変更の中身の点検は、レビュー依頼文とレビュー結果の仕事）。
- 見つけた問題を直す。
- 確定の操作（マージ、公開、記録の閉鎖、保管庫への移動など）。判定の後で何をするかは、使う側の決まりに従う。

## 証拠の強さ

| 段 | 意味 |
|---|---|
| 1. 今ここで確認 | 監査の中で、自分で実行・閲覧して確かめた |
| 2. 今の状態に対応する証跡 | 記録が残っており、その後に対象が変わっていない |
| 3. 古くなった証跡 | 記録はあるが、その後に関係する所が変わった |
| 4. 主張だけ | 「確認した」という記述だけで、記録が無い |
| 5. 未確認 | 何も無い |

段3〜5だけで支えられた条件を、満たしたことにしない。

完了条件が求める環境と違う所で確かめた記録は、その環境の証拠としては、検証の記録に二つの環境の差が書かれ、監査する側がその差を条件に照らして関係しないと判断できたときだけ段1・2に数え、その判断と理由を指摘に書く。差が書かれていない、または条件に関係するなら、その環境については段5（未確認）とする。

## 手順

### 1. 監視する範囲を決め、控えを取る

- 監視するパスは、既存の記載を鵜呑みにせず、次の和集合で作る: 実装、試験、仕様、継続して使う正本（設定・スキーマなど）、証跡を作る仕組み（試験の補助、受入の証拠になる出力を作るスクリプト）、それらが使う共有のコード。
- 監視するパスと、確定の候補にするパスは分ける。監視は広く、確定の候補は今回の作業の分だけにする。
- 開始時に作業状態の控えを取る。取り方の例は [控えの取り方](references/state-snapshot.md)。

### 2. 完了条件を読み直す

- 完了条件の一覧を、監査の時点の原典から全項目読む。
- 後から足された項目は、既に承認された条件を検証するためのものか、新しい約束（新しい規則・API・受入条件）かを区別する。新しい約束を、表現を整えただけの変更として扱わない。
- 設計の判断があれば、承認の状態を確かめる。人の決定待ちが残っていれば阻害要因、人が採っていない担当の案が残っていれば指摘にする。
- 規模の判定があれば、それが実際の差分によるものかを確かめる。完了条件の承認し直しが要るとされていて承認の記録が無いなら、阻害要因にする。続けて使う文書への影響があるのに反映も方針外の課題の記録も無いなら、指摘にする。
- 規模の判定で当たるとされた運用の作業（本番の手順、依存）と、秘密の項目・個人情報の扱いの文書について、監査の時点で成果物があり、人の承認があるかを、変更の事実と原典の参照で確かめる。当たるのに成果物も、作らないと人が決めた記録も無いなら、阻害要因にする。承認の後に中身が変わっていれば、承認し直しが要ると指摘する。

### 3. 結びつきの検査

- 道を決める。最新の規模の判定の道、作業の一覧か追跡表の有無（あれば通常の道）、完了条件の一覧が指す道のうち、重い方を採り、どれに拠ったかを書く。
- 型の一覧の「道に応じた検査」を行う。識別子の突き合わせで確かめられるものは、文の意味で判断しない。
- 識別子は、主張や記憶からではなく、監査の時点の完了条件の一覧、テストケース表、作業の一覧から写して突き合わせる。どれにも無い識別子、廃止の印が付いた項目への結びつきは指摘にする。
- 結びつきがそろっていることは、意味を満たしていることを保証しない。警告は一つずつ、問題か、許容か、誤検知かに分ける。

### 4. 受入条件ごとの意味の監査

受入条件を1件ずつ、次に対応づける。同じ要件の下にある別の条件の証拠で、欠落を埋めない。

- 作業（作業の一覧があるとき）
- テストケース
- 実際の試験、または手動の確認の記録
- 実装の該当箇所

確かめること:

- 試験の確かめ方が、結果だけでなく、否定（起きてはならないこと）と副作用まで見ているか。
- 画面・帳票・動画などの成果物そのものが受入の本体なら、その成果物を開いて見たか。試験が通ったことだけで代えない。受入の証拠があるなら、確定されているか、確定の後に関係する所が変わっていないかを確かめる。

### 5. 検証の記録の鮮度

- 各記録の対象・範囲・日時・結果を、その後の変更と照合する。関係する所が変わった記録は「古くなった証跡」とする。
- 記録が古くなった項目だけを確かめ直す。すべてをやり直さない。
- 再実行して通った不安定な試験を、成功の1件に畳まない。「再実行で通った」と分けて書く。

### 6. 残作業を分ける

| 分類 | 条件 |
|---|---|
| 阻害要因 | 完了の前に解消が必要 |
| 承認済みの除外 | 人が範囲から外すと決めた記録がある |
| 別の範囲の運用での対応 | 担当・追跡先・成功条件がすべて決まっている |
| 別の課題として切り出し済み | 追跡先の識別子がある |

担当・追跡先・成功条件のどれかが欠けている残作業は、阻害要因に入れる。

### 7. 終了時の控え

- 終了時に控えを取り直し、開始時と比べる。監視する範囲が変わっていたら、判定に「監査の途中で変化あり」と書き、「最新の状態で確認した」とは言わない。

### 8. 判定を選ぶ

| 判定 | 選ぶとき |
|---|---|
| 進めてよい | 完了条件の全項目が段1か段2で支えられ、阻害要因が無く、監査の途中で変化が無い |
| 条件付き | 足りないのが、作業を戻さずに済む確認だけ（試験の再実行、証跡の取り直し、記録の更新など）。手順を終えたら、この監査をやり直す |
| 止める | 実装・試験・仕様に戻る作業が要る、完了条件の一覧か完了の主張が無い、または阻害要因が残る |

監査の途中で変化があったときは、「進めてよい」にしない。変化した範囲を確かめ直せば済むなら「条件付き」、そうでなければ「止める」。

## 判定の形

1. 判定: 進めてよい／条件付き（次の手順を、順番を付けて具体的に）／止める
2. 完了条件の項目の表（項目、証拠、証拠の強さの段）
3. 指摘の一覧
4. 残作業（上の4分類）
5. 確定の候補にするパスと、除外するパス
6. 人に聞く一言（最終確認で何を見てほしいか）
7. 実施しなかったこと（軽い道なので要件と作業の結びつきは検査しなかった、など）

「すべて成功」と、受け入れた未解決のものは、分けて書く。

手順の根拠と、先行の手法から変えたところは [根拠と変えたところ](references/grounding.md) を見る。

## 終了条件

- 開始時と終了時の控えがある。
- 完了条件の全項目に、証拠の強さの段が付いている。
- 抜け漏れの検査を、道に応じて行ったか、行わなかった理由が書かれている。
- 判定が三つのどれかに決まり、条件付きなら次の手順が順番付きで書かれている。
- 自分で直したもの、確定の操作をしたものが無い。
