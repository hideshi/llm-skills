# 控えの取り方

監査の開始時と終了時に、作業状態の控えを取って比べる方法の例。Git を使う場合を示す。ほかの版管理でも、同じ三つ（版、未確定の変更の有無、監視するパスの内容）を記録できればよい。

## 記録するもの

| 項目 | 例 |
|---|---|
| 版 | `git rev-parse HEAD` の値 |
| 未確定の変更 | `git status --porcelain` の出力（空かどうか、含まれるパス） |
| 監視するパスの内容 | 各パスの内容のハッシュ |

## 手順の例

```bash
# 監視するパスを1行1つで書いたファイル watch-paths.txt を用意する
git rev-parse HEAD
git status --porcelain --untracked-files=all -- $(cat watch-paths.txt)
# 空白を含むパスがあるときは、1行ずつ読んで引用する
while IFS= read -r p; do
  if [ -e "$p" ]; then git hash-object -- "$p"; else echo "missing $p"; fi
done < watch-paths.txt
```

- 結果は、監査の記録に貼るか、作業の記録の置き場にファイルで残す。
- 監視するパスにディレクトリを含める場合は、その下のファイルを列挙してからハッシュを取る。後から足された未追跡のファイルも列挙に入れる。
- 消えたファイルは「missing」として記録し、変化として扱う。
- 終了時に同じ手順で取り直し、三つのどれかが違えば「監査の途中で変化あり」とする。

## 注意

- 監視するパスの一覧を、確定の候補（今回の作業でまとめるパス）と混同しない。
- 生成物（ビルドの出力など）を監視するかは、受入の証拠がそれに依存するかで決める。
