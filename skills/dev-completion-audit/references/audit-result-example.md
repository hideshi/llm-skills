# 完了判定の例

型: 完了判定
形の一例。正本は型の一覧の欄。形式・節名・置き場所は任意で、案件に既に形があればその形に従う。値はすべて作り物。

題材は、確定した請求書の明細を直せないようにする変更の監査（実装と、レビューの指摘の直しの後。直した所に絞った再レビュー `reviews/example-review-2.md` は承認）。レビュー結果（初回 `reviews/example-review-1.md` と再レビュー）に、未解決の指摘は無い。道は通常の道（最新の規模の判定と、作業の一覧があることから採った）。開始時と終了時の控えを比べて、監査の途中で監視する範囲は変わっていない。この例の識別子は、同じ題材のほかの単位の例と同じものを使う。

判定: 条件付き。手順: 1. `AC-22` の確かめ（`TC-44`）を、画面の文の直しの後の版で流す。2. 検証の記録 `runs/example-final.log` を更新する。この2つが済んだら、この監査をやり直す。

## 残作業

- 阻害要因: なし（`AC-22` の証跡の取り直しは、作業を戻さずに済む確認なので、阻害要因に数えない）。
- 承認済みの除外: 確定した請求書の取り消しの作り直し（完了条件の一覧の「やらないこと」。依頼者が範囲から外した）。
- 別の範囲の運用での対応: なし。
- 別の課題として切り出し済み: 取り消しの権限の直し（方針外の課題の記録 `OC-4`）。設計の判断 `DD-9` と作業の一覧の `TASK-3` は、人の決定で今回の作業から外して `OC-4` へ移した（決定の記録は `OC-4` にある）。今回の設計の判断と作業の一覧に、決定待ちは残っていない。

道に応じた検査（単位の本文が求める項目）: 型の一覧の「道に応じた検査」を行い、結びつきの欠けは無かった。
