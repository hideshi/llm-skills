# 判定イベント契約ガイド（Jev）

1 回の Jev 判定（または判定＋コード分岐の完了）を 1 イベントとして残すときの推奨フィールド。**値の例示にプロジェクト固有の本番数値を焼かない。**

人手最終判定（オーバーライド／最終判断）がある経路では、下記「人手最終判定イベント」を**同一契約の延長**として扱う（別スキーマを乱立させない）。

## 必須（推奨）

| フィールド | 意味 |
| :--- | :--- |
| `requirementId` | 業務判断の ID（行番号禁止） |
| `primitive` | `choice` / `score` / `noul` |
| `modelId` | 使用モデル（入力または実行時） |
| `thresholdVersion` または閾値参照 | 適用したポリシー版 |
| `validationStatus` | 実行時に有効だったゲート状態 |
| `route` | `auto` / `review` / `fallback` / `safe_default` 等（プロジェクト語彙に合わせる） |
| `latencyMs` | 呼出〜決定までの時間 |
| `outcome` | 成功 / 失敗 / タイムアウト / 例外 |
| `timestamp` | イベント時刻（TZ 方針はプロジェクト入力） |

## プリミティブ依存（該当時）

| フィールド | 意味 |
| :--- | :--- |
| `choice` / `probabilities` / `confidence` | choice |
| `score` / `probabilities` / `confidence` | score |
| `noul` | noul の確率 |

## 人手最終判定イベント（強く推奨／人手最終がある経路では必須）

運用で「人間の最終判断 → 問い／閾値改善」へつなぐための最小セット。**自由記述だけに頼らず**、不一致と理由コードで集計できるようにする。誰がいつ再較正を承認するかの業務フローは本契約の対象外（後段）。

| 項目 | フィールド例 | 意味 |
| :--- | :--- | :--- |
| 対になる Jev 回答 | `jevLabel` / `jevScore` / `jevNoul` / `jevRoute` 等＋版参照 | Jev 出力（ラベル／Score／noul／経路）と、そのとき使った **問い版（question rev）／閾値版／ポリシー版** |
| 人手最終判断 | `humanFinalLabel`（または同ラベル空間の相当） | 人手の最終回答。**Jev と同じラベル空間**で記録する |
| 不一致 | `mismatch` / `mismatchQuestions` | `agree` / `diff`。diff のときどの問い（またはどの軸）がずれたかを短い ID／キーで残す |
| 理由コード | `reasonCodes[]` | 短コード必須。自由文は補助のみ。例: `転用評価` / `必須重視` / `フラグ疑い` / `情報不足` / `Jev見落とし` / `Jev過剰警戒`（案件で拡張可。コード表は入力／政策側） |
| ケース指紋 | `caseFingerprint`（例: 案件 ID、職種ファミリー等） | 再集計・eval 境界追加のための最小識別子。**生本文は原則残さない**（下記プライバシー） |
| 版リンク | `datasetVersion` / `questionRev` / `policyVersion`（＋既存の `thresholdVersion`） | どのデータ・問い・政策・閾値版上の事象かを辿れるようにする |

### 集計切り口（メトリクス契約へ転記）

人手最終判定イベントから、少なくとも次を切れるようにする（数値目標は入力）:

- 問いごとの不一致率（`mismatch` rate per question）
- FN 寄り／FP 寄り（案件の正例定義に従う。スキルに焼かない）
- 理由コード別件数／比率

### 較正への接続（一文）

不一致＋理由コード → `NEEDS_MORE_DATA`（eval 境界追加）／問い・criteria 改訂（prompt）／Dual・ゲート調整（閾値掃引）。詳細トリアージは `jev-calibration`。

## 任意・要審査（プライバシー）

**既定は最小化**。境界を広げる場合は審査要否を記録する（既存方針と矛盾させない）。

| フィールド | 注意 |
| :--- | :--- |
| 入力本文・チケット全文・履歴書本文等 | **デフォルト禁止**。残すならマスキング＋短い保持＋審査 |
| ケース指紋に含まれる生識別子 | 可能ならハッシュ化／トークン化。方針は入力 |
| ユーザー ID・顧客 ID | 最小化。ハッシュ化方針は入力 |
| デバッグ用 raw レスポンス | 保持期間を短く |
| 人手最終の長い自由記述 | 理由コードを主とし、自由文は補助・短保持・要審査 |

## やらないこと

- イベントをプロンプト全文・生本文のダンプ置き場にしない
- 「とりあえず全部残す」を既定にしない
- 人手最終判定の理由を自由文のみにし、集計不能にする
- 本契約内で再較正の承認者・承認タイミングの業務フローを固定する
