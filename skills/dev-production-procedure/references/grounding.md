## 独自の判断

| 決まり | 理由 | 確かめ方 |
|---|---|---|
| 担当は読み取りでも本番に接続せず、手順を作って人に流してもらい、出力を受ける | 本番の資格情報と影響の範囲を担当に持たせず、操作の責任を人に置くため | 担当が本番に触れずに済まなかった件数と、人に頼んだ読み取りで足りなかった件数を記録し、分け方を見直す |
| 調べる塊と更新する塊を分け、更新する塊の先頭に同じ前提を確かめ直す読み取りを置く | 人が次の塊を流すまでの間に状態が変わりうるので、直前の確かめを外すと古い前提で変えてしまうため。一方で、調べと更新を一つにすると、判断の材料を人に見せる前に変えてしまうため | 更新の塊の先頭の確かめで止まった件数と、止まらずに古い前提で変えた件数を記録し、塊の切り方を見直す |
| 段ごとに、その段だけで判定できる確かめ方と、止める条件と止めた後の行き先を書く | 人が貼る前の出力は途中で切れることがあり、止めた後の行き先が無いと、その場で判断することになるため | 判定を誤った段と、止めた後に行き先が分からなかった件数を記録し、欄の書き方を見直す |
| 段に付ける印を、取り返せない、データを変える、止まる、外へ送る、読むだけ、の言葉で付ける | 記号や色は見落とされやすく、どの種類の危険かが流す人に伝わらないため | 印を見落として流した件数と、印の種類が足りなかった件数を記録し、印の語を見直す |
| 戻しは成果物、DB、設定を組にし、基準ごとに具体のコマンドを書き、途中の失敗のしかたごとに戻し方を表にする | 設定を変えたリリースで成果物だけを戻すと合わず、基準だけでコマンドの無い戻しはその場で書くことになるため | 戻しで設定の食い違いが起きた件数と、途中の失敗から戻せなかった件数を記録し、表の欄を見直す |
| 本番に渡す塊は手元の隔離した環境で同じ中身を流し、通ることに加えて失敗を起こして戻せることも確かめる。起こせなかった失敗は未確認と書く | 本番で初めて戻しを流すと、戻しの誤りに本番で気づくことになるため | 本番で戻しが初めて流れた件数と、未確認のまま受け入れた失敗が本番で起きた件数を記録し、確かめる範囲を見直す |
| 流し直しを省いてよいのは、保守されている正本の手順書の今の版の段だけにする。写した段の「確認済み」は今回流すまで信じない | 写した手順の注記は写した時点の事実で、環境や版が変わると誤りになるため | 写した段の「確認済み」が誤りだった件数を記録し、省いてよい範囲を見直す |
| 予行の前に予行の環境と本番との差を並べ、予行で確かめられない所は本番で読み取りで確かめる段を入れる | 予行の結果を、環境の差による違いと取り違えたり、本番の権限やデータの形の保証と思い込んだりするため | 予行は通ったのに本番で差により失敗した件数を記録し、並べる差の項目を見直す |
| 手順の承認は版に付き、承認と本番で流してよいという判断を分ける | 承認の後に中身が変わると承認の意味が無くなり、承認を流してよい合図と読むと、出す時の判断が抜けるため | 承認の後に変わった手順が承認し直されずに流れた件数を記録し、承認の持ち方を見直す |
