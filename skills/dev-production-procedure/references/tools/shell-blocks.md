# シェルの塊の作り

[SKILL.md](../../SKILL.md) の手順で、人が端末に貼って流す塊を Bash で書くときの作り方。

- 確かめた版: Bash 5.2.37。確かめた日: 2026-11-14。
- 公式の資料: 手元の Bash 5.2.37 の man ページ（`(list)`、`set -e`、`set -E`、`set -u`、ヒアドキュメント）。https://www.gnu.org/software/bash/manual/
- 【実行】は手元で流して確かめた動き、【資料】は man ページで読んだだけのこと。

## 形

```bash
# ===== ここから: <ホスト> の <利用者> で流す =====
(
  set -Eeuo pipefail
  : "${APP_ROOT:?APP_ROOT が未設定なので止める}"
  [ "$(id -un)" = "<利用者>" ] || { echo "利用者が違うので何もせずに止める"; exit 1; }

  # 前提の確かめ（読み取りだけ）。満たさなければ、何も変えずに終わる
  # ...

  trap 'echo "失敗: 次は <立て直しか戻しの段> を流す"' ERR
  # 影響のある操作
  # ...

  # この塊だけで成否を判定できる確かめ
  # ...
)
# ===== ここまで: <ホスト> の <利用者> =====
```

- `( ... )` で包むと、中は子のシェルで動く。中の変数の代入は、終わった後に残らない【実行】。`set -e` や `exit` で止まっても、貼り付けた側の対話のシェルは終わらない。
- 先頭と末尾の `#` の行は、流すホストと利用者の目印。Bash の対話のシェルでは既定でコメントとして扱われ、一緒に貼っても何も起きない。流す先のシェルが Bash かは、担当×ホスト×利用者の表に書いて、人に確かめてもらう（対話でコメントを扱わない設定のシェルでは、コマンドとして走る）。
- 確かめる対象の場所などの変数は、`${VAR:?}` で未設定なら止める。既定の値に黙って落とさない（誤った場所を確かめて全部「無い」になるのを防ぐ）。
- `set -E` を付けると、`ERR` の罠が関数、コマンド置換、子のシェルに引き継がれる。付けないと引き継がれない【資料】。`su -c` や `bash -c` の内側には外側の罠が効かないので、内側に自分の罠を書く。
- `set -e` は、`if` の条件の中、`&&` と `||` の最後以外、`!` で反転したコマンドの失敗では止まらない。パイプの最後以外の失敗でも止まらないが、形の塊は `pipefail` を付けているので、パイプの途中の失敗でも止まる【資料】（`if` の中の失敗で止まらないこと、`pipefail` つきで `false | true` が止まって罠が動くことは【実行】）。
- `ERR` の罠が動かない止まり方がある。未設定の変数（`set -u` や `${VAR:?}`）で止まったとき、明示の `exit` で止まったとき【実行】。影響のある操作の区間では、未設定の変数で止まらないよう、使う変数を区間の前で全部確かめておく。区間の中で `exit` するときは、自分で案内を出してから終わる。
- `local x=$(コマンド)` のように、代入と宣言を一つの文にすると、コマンドの失敗が隠れて先へ進む【実行】（しかも罠の案内の文が変数に入る）。宣言と代入を分ける（`local x; x=$(コマンド)`）。

## 全部を数えてから終わる確かめ

確かめを並べる塊で `set -e` のまま確かめを流すと、最初の失敗で止まり、合計が出ない。確かめは条件の中で流して数え、最後に失敗があれば0でない値で終わる。

```bash
(
  set -uo pipefail
  ok=0; ng=0
  # check <表示する名前> <コマンド...>。表示には名前だけを出し、引数は出さない
  check() { local name="$1"; shift; if "$@"; then ok=$((ok+1)); else ng=$((ng+1)); echo "NG: $name"; fi; }
  check "置き場所がある" test -d "${APP_ROOT:?}"
  # ...
  echo "通った: $ok  落ちた: $ng"
  [ "$ng" -eq 0 ]
)
```

- `check` に渡すのは、一つのコマンドか、自分で失敗をまとめて返す関数だけにする。途中に失敗のある複数のコマンドの関数を渡すと、最後のコマンドが通れば合格になる【実行】。
- 失敗の表示に、引数をそのまま出さない（資格情報や所在を引数に取る確かめで、値が映る）。表示する名前と、流す引数を分ける。

## 書かない・使わない

- 本文やコードを書き出すときに、引用符の無いヒアドキュメント（`<<EOF`）を使わない。中の行は、変数の展開とコマンド置換を受ける【資料】（`$(...)` が実行されることは【実行】）。`<<'EOF'` か、ファイルを書く道具を使う。
- 設定の全文を表示しない（`cat` で設定のファイルを出すと、認証の設定や中継先の資格情報が映りうる）。要る項目の名前だけを出す。
- 環境の変数は名前だけ、`PATH` は該当する部分だけを表示する。
- ポートの番号を文字の一部として拾う検索（`grep 80` のような）で、待ち受けを判定しない（`8080` にも当たる）。番号は区切りまで含めて照らす。
- 読み取りのつもりの道具が、常駐の処理を起こすことがある（管理の道具の状態の表示が、管理の処理を立ち上げる、など）。使う前に、その道具の公式の説明で確かめる。
- 止めるときの名前での一括の停止（`pkill -f`）は、自分のシェルの引数にも当たりうる。
- 設定の読み直し（reload）は、名前だけで止まらないとみなさない。処理中の要求を待つかと期限を、公式の資料と有効な設定で確かめる。
