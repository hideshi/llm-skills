# 根拠の別紙の作成と照合の手順

[開発スキル群の作り方の規約](dev-skills-conventions.md) §6 に従い、単位ごとの `references/grounding.md` を作るとき・直すときの手順と判断基準をまとめる。

## 1. 作成の順序

出典から手順を逆算せず、必ず次の順で進める。

1. **本文の手順を棚卸しする**: 対象単位の `SKILL.md` と `references/` を読み、核となる手順・数値・目安・禁止事項・境界条件をすべて抜き出す。
2. **候補を探す**: 各手順の根拠になりそうな先行の手法や仕様を探す。記憶や生成した文だけで書かず、この段階で出典の候補を挙げるにとどめる。
3. **出典を実際に開く**: 挙げた出典を開いて確かめる。確認できた粒度を超えて細部（章番号、節番号、task 番号、DOI の末尾など）を補わない。
   - 原文を開けた場合は、本文を照合して「原典を読んだ」にする。
   - 公式目次、出版社の書誌ページ、Crossref、要旨や二次解説だけで確認した場合は、その範囲までを書き、「書誌と二次資料で確かめた」にする。
   - 開けなかったもの、単一の原典を特定できないものは「未確認」にする。
4. **該当しない手順を切り分ける**: 先行の手法に当てはまらない手順や、下の「こじつけの判定」に当たるものは、無理に「先行の手法」に入れず「独自の判断」に置く。「先行の手法」が 0 行でも異常ではない。
5. **見出し・文言を `SKILL.md` と突き合わせる**: 「手順の箇所」の番号・見出しが `SKILL.md` に実在するか、本文の「目安」「〜してよい」を別紙で「上限」「必須」に強めていないかを確認する。

一気に多数の単位をまとめ書きしない。数単位ずつ作り、都度下の「5. 照合とレビュー」を通す。

## 2. 「確かめた水準」の導き方

水準は安全側へ一律に倒さず、**実際に何を開いたか**から機械的に決める。

| 水準 | 選ぶ条件 | 必ず添えること |
|---|---|---|
| 原典を読んだ | 無料で読める仕様書・RFC・論文・記事の該当箇所を実際に開いて読んだ、または単位内の記録に原文との照合履歴がある | 読んだ原典の URL・節・版、または原文照合の記録ファイルと日付 |
| 書誌と二次資料で確かめた | 書籍の出版情報・公式目次・DOI 書誌・要旨・技術解説記事で確認した | 何で確認し、何が未読かを書く（例: `（章構成・要旨で確認。本文は未読）`） |
| 未確認 | 出典を開いて確認できなかった、または確立した名前はあるが単一の原典を特定できない | 出典欄は `—` にし、手法名だけ（例: `〜と呼ばれる手法`）を書く |

同一行に複数の出典を並べる場合は、多くても二、三本までにする。確認水準が混ざる出典を1行に詰め込まず、確認できたものと未確認のものを分ける。

## 3. こじつけの判定

次のどれかに当たるときは、「先行の手法」に置かず「独自の判断」へ移す。

- 元の手法が対象とする前提・単位・領域（例: 分散プロセッサの合意、チーム規模別の手法選定、製造ラインの治具）と、この単位の作業の性質が離れており、手法の中核を別のものへ読み替えている。
- 「変えた・足したところ」の説明が元の手法より大きく、出典を辿ってもなぜこの単位の手順になるのかが読者に伝わらない。

## 4. 「独自の判断」の確かめ方の型

「独自の判断」は仮説として扱う。「〜が書かれているかを見る」という存在確認の文は、書式の点検にはなっても仮説の検証にならない。原則として、**何を観測したらこの決まりを見直す・捨てるか**を添える。

| 型 | 書き方の例 |
|---|---|
| 見逃し・手戻りの件数を見る | 3回で見逃した揺れが後から見つかった件数を記録し、回数の目安を見直す |
| 条件別・前後で比べる | 別モデルへ回した回と同一モデルの回で、指摘の種類と独立性に差が出たかを記録で比べる |
| 抑止した事象のその後の結果を見る | 引き上げを抑制した案件で、後の工程に設計漏れや手戻りが起きなかったかを記録で確かめる |

## 5. 照合とレビュー

作成の後の点検は、書いた側自身ではなく独立した照合で行う。

- **形式と構造の検査**: `python3 -I scripts/check_dev_skills.py` を実行し、エラーが 0 件であることを確かめる（`--grounding-warnings` で存在確認型の確かめ方などの警告も確認する）。
- **URL・DOI の到達確認**（ネットワーク接続がある環境で任意に実行）: `python3 -I scripts/check_grounding_links.py` でリンク切れと DOI の照合を行う。
- **独立レビュー**: 照合担当（別モデルや別の呼び出し）には、`SKILL.md`・`references/`・出典の URL / DOI だけを渡し、執筆側の要約や「問題ない」という結論を渡さない。章・節・DOI の細部、`SKILL.md` の表現との強弱のずれ、こじつけの有無を突き合わせる。
- **直した後の記録**: 修正したら `## 改善の記録` に日付（`YYYY-MM-DD`）、何を、なぜ、どの出典・根拠で変えたかを 1 行足す。
