# 版管理の作業のプロファイルのモデル

`skills/dev-profile-version-control` の工程の順序、条件、戻る流れ、人の決定を TLA+ で表し、TLC で検査する。共通の注意は [../README.md](../README.md)。

## 確かめる性質

| 性質 | プロファイルの決まり |
|---|---|
| `IsolatedBeforeWork` | 作業場所を作ったときは、ファイルと保存先・実行枠・依存の隔離を確かめてから工程 `work` へ進む |
| `TableBeforeResolved` | 衝突解消を終えた時点で、統合の判断表がある（表を作ってから編集する順序そのものは単位の中の手順で、モデルでは工程 `resolve` の完了に畳んでおり検査しない） |
| `ContractDecisionBeforeDone` | 未決の契約の変化があるなら、人の決定（`contract-ask`）の前に解消を終えない |
| `ApprovalBeforeDestructive` | 印に「取り返せない」が付く復旧または外部道具の導入では、2回目以降も含め毎回 `destructive-ok` の承認後にだけ実行する（`nexec <= napp`） |
| `AbortedNeverExecutes` | 人が工程 `destructive-ok` で中止を決めた場合、中止で終わり、中止した時点の実行回数（`execAtAbort`）から破壊的操作が増えない |
| `IntegrationOrDiscardBeforeCleanup` | 作業場所の片付け（`cleanup`）は、工程 `integrate` で統合完了・確認または破棄承認を終えた後（あるいは片付け入口）だけに行う |
| `CleanupBeforeDone` | 作業場所を使い片付けも依頼された場合、人が中止と決めたときを除き工程 `cleanup` の片付けを終えてから完了する |
| `Terminates` | どの依頼でも、いつか終わる（公平性の下で） |

行き止まりが無いこと（デッドロックの検査）と、どの工程にもたどり着けること（`-coverage`）も見る。

## 仮定と範囲

- 入口は五つ（作業場所を作る、統合する、衝突を解く、トラブルから戻す、片付ける）。初期状態で非決定に選ぶ。
- 入口を「片付ける（`cleanup`）」にした場合、`integrated`（および任意の `discardApproved`）は事前成立として初期化される。直接の片付け依頼における統合完了または破棄承認の実確認は、単位 `dev-isolated-workspace` の手順4に委ねる。
- 統合せず破棄する人の承認（`discardApproved`）は、モデルの外で得たものとして初期状態で与える。承認を得る人の工程は表さない。破棄の承認と取り込みのトラブル（`mergeTrouble`）が同時に立つ組み合わせも探索するが、実際には起きにくい。
- 工程 `integrate` の「統合と確認を終えた」は、プロファイルの工程の間の決まり（原典の方法と宛先、取り込み前の控え、統合先での確かめを検証の記録に残す）を満たしたものとして、工程 `integrate` の通過で `integrated` を立てる。中身の確かめは単位と実装側に委ねる。
- 工程 `destructive-ok`（承認・中止）は訪問ごとに非決定に分岐させ、1回目は承認して2回目は中止する経路も探索する。
- 変更前の控えの取得や、Q1・Q2 の着地判定、隠れ衝突の検査など単位内部の手順は抽象化し、各工程の完了に畳んでいる。
- 復旧と衝突解消の行き来（`resolve` と `recover`）、作業・取り込みからの復旧復帰（`work`・`integrate` と `recover`）は、各箇所の復旧済みフラグにより無限ループしない仮定を置いている。

## 検査の記録

| 日付 | 道具 | 結果 |
|---|---|---|
| 2026-11-13 | TLC 2.19（tla2tools 2024-08-08）、Java 21（`-Xmx1g`、2並び） | 36,152 状態（全 43,296 生成、深さ 22）で違反なし、行き止まりなし、`Terminates` が成り立つ。`-coverage` で全部の動作が起きる。2回目以降の工程 4b 承認を飛ばすと `ApprovalBeforeDestructive`（`nexec <= napp`）が破れることを確かめた |
| 2026-11-13 | TLC 2.19（tla2tools 2024-08-08）、Java 21（`-Xmx1g`、2並び） | `AbortedNeverExecutes` を中止時の実行回数（`execAtAbort`）との比較に改めた後も、36,152 状態（全 43,296 生成、深さ 22）で違反なし、行き止まりなし、`Terminates` が成り立つ。4b の中止の後に工程4へ戻して実行できるようにすると `AbortedNeverExecutes` が破れることを確かめた |
| 2026-11-14 | 同上 | 工程の番号を識別子に置き換えた版: 36,152 状態（全 43,296 生成、深さ 22）で違反なし。置き換えの前と状態数・深さが同じで、EdgeProbe の矢印も対応表で写すと一致した。モデルを対応表で旧い番号に戻すと、識別子と同じ字の入口の名前（`"workspace"`、`"integrate"` など）を除いて、前の版と字句が一致した。承認を飛ばして復旧を実行すると `ApprovalBeforeDestructive` が破れることを確かめ直した |

2026-11-14 に工程の番号を識別子に置き換えた。これより前の記録にある番号は、[対応表](../../../docs/dev-skills-conventions.md#付録-工程の識別子の対応表)で読み替える。
