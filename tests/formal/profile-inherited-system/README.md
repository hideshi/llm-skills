# 引き継いだシステムのプロファイルのモデル

`skills/dev-profile-inherited-system` の工程の順序、条件、戻る流れ、人の決定を TLA+ で表し、TLC で検査する。共通の注意は [../README.md](../README.md)。

## 確かめる性質

| 性質 | プロファイルの決まり |
|---|---|
| `AskBeforeCatalog` | 地図から前任者や人に問う事実確認が出たら、目録へ進む前に問う（前任者がいなければ不明として残す） |
| `LedgerOnlyIfPersonal` | 個人情報の台帳は、個人の情報を扱うと人が決めたときだけ作る |
| `LedgerBeforeApproval` | 個人の情報を扱うなら、承認の前に台帳がある |
| `AnswersBeforeApproval` | 承認の前に、目録と台帳の問いは、答えを反映したか期限つきで保留にした |
| `DoneOnlyApproved` | 終わるのは、人が承認したときだけ（承認しないときは直す先へ戻り、直すと承認はやり直し） |
| `Terminates` | どの依頼でも、いつか終わる（公平性の下で） |

## 仮定と範囲

- 問いの有無、前任者がいるか、個人の情報を扱うか、保留にするか、承認しないか、直す先は、初期状態で非決定に選ぶ。
- 前任者への問い、目録と台帳の答え、期限つきの保留、承認しないことは、それぞれ1回まで起きうるとする。
- 表していないもの: 単位の中身（値を読まない取り出し方、本番を読まないこと、正誤の履歴）、法的な根拠を外へ渡すこと、承認の版の中身（直したら承認がやり直しになることは、状態の更新で表すだけ）、中断と再開。
- `DoneOnlyApproved` は弱い性質で、終わりへの唯一の動作が承認を立てるので、ほぼ破れない。直した後に承認し直さずに終わる道は、モデルの作り（承認しないときは必ず直す先へ戻り、もう一度 `inventory-ok` を通る）で防いでいて、性質としては確かめていない。

## 検査の記録

| 日付 | 道具 | 結果 |
|---|---|---|
| 2026-11-14 | TLC 2.19（tla2tools 2024-08-08）、Java 21（`-Xmx1g`、2並び） | 3,752 状態で違反なし、行き止まりなし、`Terminates` が成り立つ。問いを飛ばすと `AskBeforeCatalog` が、台帳を飛ばすと `LedgerBeforeApproval` が、人の確かめを飛ばすと `AnswersBeforeApproval` が破れることを確かめた |
| 2026-11-14 | 同上 | レビュー（別のモデル2つ）を受け、地図が既にあるときの 1 → 4（`mapExists`）を足した版。6,880 状態で違反なし、行き止まりなし、`Terminates` が成り立つ |
| 2026-11-14 | 同上 | 工程の番号を識別子に置き換えた版: 6,880 状態（全 7,648 生成、深さ 18）で違反なし。置き換えの前と状態数・深さが同じで、EdgeProbe の矢印も対応表で写すと一致した。モデルを対応表で旧い番号に戻すと、前の版と字句が一致した。台帳を飛ばすと `LedgerBeforeApproval` が破れることを確かめ直した |
