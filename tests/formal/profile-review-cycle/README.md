# レビューの一巡のプロファイルのモデル

`skills/dev-profile-review-cycle` の工程の順序、条件、戻る流れ、人の決定を TLA+ で表し、TLC で検査する。共通の注意は [../README.md](../README.md)。

## 確かめる性質

| 性質 | プロファイルの決まり |
|---|---|
| `EvidenceBeforeBrief` | 受入の証拠は確定してから依頼文に添える（工程 `brief` と、工程 `re-review-round` の依頼文） |
| `BriefBeforeReview` | 依頼文を書いてからレビューする |
| `AuditAfterApproval` | 承認されてから監査する |
| `ReviewIndependent` | レビューする担当（工程 `review` と `re-review-round`）は、作った側の説明を読んでいない別の担当。中断して記録で再開した担当は、前の担当と同じ側として扱う |
| `ApprovedChangeNeedsHuman` | 中断の間に、人が承認した成果物が変わっていたら、人に確かめてから工程に戻る |
| `ResumeReturnsToSaved` | 再開したら、中断した工程に戻る（動作の性質。割り込みを突き合わせの書き出しから外したので、戻り先はこれで見る） |
| `Terminates` | どの依頼でも、いつか終わる（公平性の下で） |

行き止まりが無いこと（デッドロックの検査）と、どの工程にもたどり着けること（`-coverage`）も見る。

## 仮定と範囲

- 変更要求は最大2回、人への差し戻しと、監査の「条件付き」「止める」は各1回まで起きうるとする。
- 中断と再開（工程の間の決まり）は、工程 `evidence`・`brief`・`review`・`rework`・`re-review-round`・`audit` のどこでも1回まで起きうる割り込みとして表す（"R" が再開、"HR" が再開の時の人の確認）。遷移の表に載らないので、突き合わせの書き出し（`EdgeProbe`）からは外す。そのため戻り先は突き合わせでは見ておらず、`ResumeReturnsToSaved` で見る。再開は中断した工程の最初から（やり直し）。人の決定待ち（"H"）の間には中断が起きない形にしている。人が承認済みの変化を認めた後の戻り先（証拠のやり直しなど）は、表さずに元の工程へ戻す。
- 担当の側は `actor`（作った側／レビューする側／監査する側）と、作った側の説明を読んだか（`authorView`）で表す。再開した担当は記録を読むので、記録を書いたのが作った側なら説明を読んだことになる。
- 表していないもの: 工程の途中で切れること（工程は一つの動作として表すので、途中で切れたときにやり直す決まりは確かめていない）。同じ指摘で2回合意できないときの人の決定は、2回目の変更要求の後に承認へ倒して表す。

## 検査の記録

| 日付 | 道具 | 結果 |
|---|---|---|
| 2026-11-13 | TLC v1.7.4、Java 21（`-Xmx1g`、2並び） | 1,336 状態で違反なし、行き止まりなし、`Terminates` が成り立つ。`-coverage` で全部の動作が起きる。遷移の表・流れ図との突き合わせで、流れ図に「直した所が証拠に関係するなら 0 をやり直す」（3→0→4）が無かったのを見つけて直した |
| 2026-11-13 | TLC 2.19（tla2tools 2024-08-08）、Java 21（`-Xmx1g`、2並び） | 中断と再開を工程0〜5の割り込みとして足し、`ReviewIndependent` と `ApprovedChangeNeedsHuman` を加えた版。14,888 状態で違反なし、行き止まりなし、`Terminates` が成り立つ。`-coverage` で全部の動作が起きる。わざと壊して確かめた: 再開した担当が前の側を引き継がないと、依頼文の前の再開からレビューへ進んで `ReviewIndependent`（と `BriefBeforeReview`）が破れる。再開の時の人の確認を飛ばすと `ApprovedChangeNeedsHuman` が破れる |
| 2026-11-13 | 同上 | レビュー（別のモデル）で「工程1で中断したら工程3に戻る」に壊しても、どの検査にも掛からないと分かった（割り込みを突き合わせの書き出しから外したため）。`ResumeReturnsToSaved` を足し、同じ壊し方でこの性質が破れることを確かめた。14,888 状態で違反なし |
| 2026-11-14 | 同上 | 工程の番号を識別子に置き換えた版: 14,888 状態（全 16,984 生成、深さ 19）で違反なし。置き換えの前と状態数・深さが同じで、EdgeProbe の矢印も対応表で写すと一致した。モデルを対応表で旧い番号に戻すと、識別子と同じ字の旗の名前（`"evidence"`）を除いて、前の版と字句が一致した。再開の時の人の確認を飛ばすと `ApprovedChangeNeedsHuman` が破れることを確かめ直した |

2026-11-14 に工程の番号を識別子に置き換えた。これより前の記録にある番号は、[対応表](../../../docs/dev-skills-conventions.md#付録-工程の識別子の対応表)で読み替える。
