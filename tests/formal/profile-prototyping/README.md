# 試作（プロトタイピング）のプロファイルのモデル

`skills/dev-profile-prototyping` の工程の順序、条件、戻る流れ、人の決定を TLA+ で表し、TLC で検査する。共通の注意は [../README.md](../README.md)。

## 確かめる性質

| 性質 | プロファイルの決まり |
|---|---|
| `BuildIsolated` | 試作（コード・ワイヤー）を作るのは、場所を分けた後 |
| `WireNeedsScreen` | ワイヤーの単位で試作するのは、もとにする画面の設計があるときだけ |
| `ShowAfterBuild` | 人に見せるのは、コードかワイヤーを作った後 |
| `DecideAfterShow` | 進め方を人が決めるのは、人に見せた後 |
| `DecideBeforeCleanup` | 片付けに入るのは、進め方を人が決めた後 |
| `DiscardBeforeClean` | 片付けるのは、破棄の承認を確かめた後 |
| `CleanBeforeFinal` | 最終確認は、片付けの後 |
| `Terminates` | 受付から始めて、いつか終わる（公平性の下で。切り替え・直し・もう一周は各1回までという制約つき） |

## 仮定と範囲

- 画面の設計の有無、動くもので確かめる問い（モックで人に見せる問いを含む）の有無、試作の切り替え、見せた後の直し、もう一周は、初期状態で非決定に選ぶ（確かめたい問いは、動くものかワイヤーのどちらかで確かめる、という制約つき）。
- `build` と `wireframe` の間の切り替えは両方向あわせて1回まで（`crossed` を両方向で共有）、`show-ask` からの試作の直し、`direction-ask` からのもう一周は、それぞれ1回まで起きうるとする。
- 入口は `intake` だけとする。途中の工程（`show-ask`、`direction-ask`、`cleanup`）から入る依頼は表さない。
- 進め方の決定の「本開発に進む」と「捨てる」は区別しない（どちらも片付けに進む）。
- 打ち止めに当たった場合の条件の細かい言い分けは表さない（その場合も `show-ask` を通る決まりは、遷移の条件の文だけに残る）。
- 統合や持ち出しの動きはモデルに無い。`DiscardBeforeClean` は、破棄の承認が片付けに先行することだけを確かめる（「統合しない」こと自体は、このモデルでは確かめていない）。
- 表していないもの: 単位の中身（場所の分け方、ワイヤーの作り方）、打ち止めの具体的な条件、中断と再開、学びを受ける次の組み合わせ（この組み合わせの外）。

## 検査の記録

| 日付 | 道具 | 結果 |
|---|---|---|
| 2026-11-16 | TLC 2.19（tla2tools 2024-08-08）、Java 21（`-Xmx1g`、2並び） | 2,286 状態（2,478 生成、深さ 15）で違反なし、行き止まりなし、`Terminates` が成り立つ。破棄の承認なしで片付ける写しで `DiscardBeforeClean` が、場所を分けずに作る写しで `BuildIsolated` が、画面の設計なしでワイヤーに直す写しで `WireNeedsScreen` が破れることを確かめた |
| 2026-11-16 | 同上（`DecideAfterShow` を足した後） | 2,286 状態（2,478 生成、深さ 15）で違反なし、行き止まりなし、`Terminates` が成り立つ。人に見せる前に進め方を決める写しで `DecideAfterShow` が破れることを確かめた |
