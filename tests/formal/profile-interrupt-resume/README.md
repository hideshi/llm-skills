# 中断と再開のプロファイルのモデル

`skills/dev-profile-interrupt-resume` の工程の順序、条件、戻る流れ、人の決定を TLA+ で表し、TLC で検査する。共通の注意は [../README.md](../README.md)。

## 確かめる性質

| 性質 | プロファイルの決まり |
|---|---|
| `SnapshotBeforeResume` | 中断した側から再開するときは、工程 `handoff` を通ってから工程 `resume` へ（工程 `handoff` の中の「控えを先に取る」順は見ていない。下の範囲を見る） |
| `ReceiptBeforeContinue` | 別の担当に渡したときは、受け取りを確かめてから続ける。届かなかったときは、人に確かめて（伝言を頼んで）から続ける |
| `ComparedBeforeContinue` | 続きに戻るのは、今の状態と照らした後か、委任の結果を統合した後（委任だけで受け取りを確かめたとき、届かず人が続け方を決めたときを除く） |
| `HumanBeforeContinue` | 人に確かめる条件に当たるなら、人の決定の前に続きへ戻らない |
| `ResultIssueNeedsHuman` | 委任の結果が範囲を超えた・失敗した・人の決定が要るなら、人の決定の前に続きへ戻らない |
| `Terminates` | どの依頼でも、いつか終わる（公平性の下で） |

行き止まりが無いこと（デッドロックの検査）と、どの工程にもたどり着けること（`-coverage`）も見る。

## 仮定と範囲

- 入口は三つ（中断・委任する、記録から再開する、委任の結果が届いた）。初期状態で非決定に選ぶ。
- 中断の間（セッションが切れている間）は、工程 `handoff`・`receipt`・`resume-ask` から工程 `resume` への移り変わりの中に畳む。中断の長さや、その間の変化の中身は表さず、照らした結果を `approvedChanged` などの値で与える。だから、照合そのもの（何が変わったかを正しく見つけるか）は確かめていない。
- 人による記録の選び直しは1回まで起きうるとする。選び直した後は人の決定が済んだものとして扱う。
- 記録か控えが無い（`noRecord`）のは、再開の入口から入ったときだけ意味を持つ。
- 表していないもの:
  - 工程 `handoff` の中の順序（控えを記録より先に取る）。`snap` と `recorded` は同じ動作で立つ。
  - 担当の側の引継ぎ（再開した担当を前と同じ側として扱う）。これは、戻った先の組み合わせのモデル（レビューの一巡）の `ReviewIndependent` で見る。
  - 監査・レビューの途中で切れたときのやり直し（工程の途中はモデルに無い）。
  - 二重の再開（同じ記録から二度再開しない）。
  - 戻った後の元の組み合わせの工程（工程 `return` の後はモデルの外）。人が承認済みの変化を認めた後の戻り先（承認し直しなど）も、元の組み合わせの決まりに任せる。

## 検査の記録

| 日付 | 道具 | 結果 |
|---|---|---|
| 2026-11-13 | TLC 2.19（tla2tools 2024-08-08）、Java 21（`-Xmx1g`、2並び） | 6,152 状態で違反なし、行き止まりなし、`Terminates` が成り立つ。`-coverage` で全部の動作が起きる。人に確かめる判定を外すと `HumanBeforeContinue` が、工程2を飛ばすと `ReceiptBeforeContinue` が破れることを確かめた |
| 2026-11-13 | 同上 | レビュー（別のモデル）を受けた版: 工程2を単位の工程にし、届かなければ工程4へ。工程3b（委任の結果を統合する）と入口の三つ目を足した。17,248 状態で違反なし、行き止まりなし、`Terminates` が成り立つ。`-coverage` で全部の動作が起きる。届かないのに工程3へ進めると `ReceiptBeforeContinue` が、結果の問題を人に回さないと `ResultIssueNeedsHuman` が、人に確かめる判定を外すと `HumanBeforeContinue` が破れることを確かめた |
| 2026-11-14 | 同上 | 工程の番号を識別子に置き換えた版: 17,248 状態（全 20,320 生成、深さ 8）で違反なし。置き換えの前と状態数・深さが同じで、EdgeProbe の矢印も対応表で写すと一致した。モデルを対応表で旧い番号に戻すと、識別子と同じ字の入口の名前（`"resume"`）を除いて、前の版と字句が一致した。人に確かめる判定を外すと `HumanBeforeContinue` が破れることを確かめ直した |

2026-11-14 に工程の番号を識別子に置き換えた。これより前の記録にある番号は、[対応表](../../../docs/dev-skills-conventions.md#付録-工程の識別子の対応表)で読み替える。
