# 型の結びつきのモデル（試行）

[型の一覧](../../../skills/dev-shared/references/artifact-types.md)の「識別子と結びつき」の決まりのうち、通常の道の抜け漏れの検査 1〜8 と、それが支える結びつきを Alloy で表し、決まりそのものの矛盾と穴を探す。案件の成果物は検査しない。正本は型の一覧で、このモデルは写し（写した版は main の f8dcf1f の型の一覧）。

試行として、仕様化の中核（要件、受入条件、テストケース、作業、業務規則、設計の判断）だけを表した。画面と文面（検査 11〜15）、ドメインモデル（9、10）、軽い道は表していない。

## 仮定と範囲

- 「今回の範囲」は、モデルの中のものすべてとする。
- 検査は文のとおりに写し、検査の文に無い条件（廃止したものを除く、など）は足していない。結びつきの表の多さは事実にしない。受入条件 → 要件の「1つ以上」と、テストケース → 受入条件の「1つ以上（無ければ出どころ）」は、検査 1〜8 に見る項目が無い（検査 1 は要件 → 受入条件の向き）ので、検査を通れば成り立つかを主張（H12、H9）で見る。
- 文の読みを選んだ所:
  - 検査 2 の「否定を含む受入条件には、否定のケースがある」は、テストで確かめない理由がある受入条件にも掛かると読んだ（S5 で確かめた）。
  - 検査 7 の「テストで確かめない規則には、手段と理由がある」は、第1文と同じく有効な規則に限ると読んだ。
  - 規則の「満たすケース」は、規則を指すテストケースのうち「破るケース」の印の無いものとした。印はケースごとで、規則ごとではない。
- 検査 8 の「存在し」は表せない（指す先は必ずモデルの中の規則なので、指す先の無い参照を作れない）。確かめていない。
- 出どころは種類を区別しない（問題台帳の問題、回帰の基準の検証点などを1つの集合にまとめた）。
- 廃止したテストケースと作業、「決定待ち」の作業は表していない。
- 範囲は、どのコマンドも各集合を最大5個まで。反例が無いと言えるのは、この範囲の中だけ。範囲を変えて流すときは、写しを作って ` for 5` を ` for 3` などに置き換える。
- 結びつきの形だけを見る。受入条件の文が判定できる形か、のような中身は見ない。

## 流し方

[Alloy の道具の資料](../../../skills/dev-formal-model-check/references/tools/alloy.md)のとおり。

```sh
java -Xmx1g -jar org.alloytools.alloy.dist.jar exec -q -f -c '*' -t json TypeLinks.als
```

結果は `TypeLinks/receipt.json` に出る（このフォルダはコミットしない）。各コマンドに `"solution"` があれば、例か反例がある。

## 見つかったこと（2026-11-17）

どれも、モデルの反例と、決まりの文との対応を読んで確かめたところまで。案件の成果物で再現したものではない。決まりを直すべきかは人が決める（穴ではなく、ほかの所で守っている、という判断もありうる）。

1. **作業が終わっても、受入条件のテストが一度も通っていないことがある**（H1、H2）。経路は2つある。
   - 受入条件のテストケースが既にあるもので、どの作業にも結ばれていない。検査 5（新しく足すケースだけ）にも検査 6（作業に結んだケースだけ）にも掛からない（H1）。
   - ケースが全部新しくても、受入条件に結んだ作業と、そのケースを結んだ作業が別でありうる。前者が全部終わっても、後者が終わっていなければ通っていない（H2）。検査 3 と検査 5 が別々の作業で満たせ、作業が結ぶケースとその作業の受入条件の対応も求めていない（H3）。
2. **否定のケースと、業務規則の満たすケース・破るケースも、同じ理由で通らないまま終われる**（H4、H5）。
3. **廃止の扱いが、両方向にずれている**。
   - 弱い向き: 廃止されていない要件の受入条件が全部廃止されていても通る（H6。検査 1 は、廃止した受入条件も数える）。廃止されていない受入条件が、廃止した要件だけに属していても通る（H7。受入条件の属する要件が廃止かどうかを見る検査が無い）。
   - 強い向き: 廃止した受入条件にも、作業への結びつきと、テストケースか理由が要る（S1、S2）。廃止した要件にも受入条件が要る（S3）。廃止した受入条件が指す規則も、検査 8 で有効であることを求められる（S4）。検査 1〜3 と 8 は「すべての」「指す」と書き、廃止したものを除いていない。
4. **テストケースが、廃止した規則や仮説の規則を確かめていても通る**（H8）。検査 8 は受入条件と設計の判断が指す規則だけを見る。
5. **受入条件も出どころも無いテストケースが通る**（H9）。**どの要件にも属さない受入条件も通る**（H12）。結びつきの表は、テストケース → 受入条件を「1つ以上（無ければ出どころ）」、受入条件 → 要件を「1つ以上」と決めるが、検査 1〜8 にそれを見る項目が無い（作業の側は検査 4 で見ている）。
6. **終わった作業の、先に終わっている必要がある作業が終わっていなくても通る**（H10）。依存の輪（自分自身を含む）も通る（H11）。作業に分ける単位の本文の「依存が一方向」は、並べて進めてよい作業どうしの条件で、輪そのものを禁じる決まりではない。輪を禁じる決まりは、型の一覧にも単位の本文にも見当たらない。

## 人に決めてもらうこと（2段目の前に）

- 既にあるテストケースを作業に結ばないのは意図どおりか（回帰として別に通す前提か）。意図どおりなら、1の1つ目の経路は穴ではなく、どこで通すかの記載の問題になる。
- 検査 2 の「否定を含む受入条件には、否定のケースがある」は、テストで確かめない理由がある受入条件にも掛かるか。
- 検査 1〜3 と 8 の「すべての」「指す」は、廃止したものを含むか。
